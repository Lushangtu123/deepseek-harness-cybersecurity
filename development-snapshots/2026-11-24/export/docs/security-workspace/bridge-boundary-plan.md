## HOST-F3：写操作的结果未知

当前代理的队列、连接、响应头超时共用连接中断与重新加载提示。对 POST，连接失败不等于操作未执行：上游可能已收到请求，甚至已提交写入。现有代理没有自动重放 POST，但提示仍会诱发用户重试。

拟分别记录：

| 回执 | 条件 | 页面动作 |
| --- | --- | --- |
| 未转发 | 有明确证据请求尚未交给上游 | 展示原因，允许用户重新发起 |
| 结果未知 | 已转发、可能已转发，或无法证明未转发 | 保留原任务标识，先查询原任务，不提示重复提交 |
| 已完成 | 原请求返回可关联的完整结果 | 展示该结果 |

沿用可证明的端到端请求/任务标识；上游没有只读查询能力时保留未知，避免凭代理随机 UUID 声称可恢复。回执不保存请求体、密钥、cookie 或私人项目内容。新连接不自动重放写入；读取失败也不声称事务回滚。

验收：合成上游收到一次 POST 后故意延迟响应；代理显示结果未知、计数仍为一次，后续查询关联原任务。覆盖连接前拒绝、排队期限、发送中断、响应头超时、响应体中断、旧标签页、用户二次点击与无查询接口情况。

## HOST-F1：VM 内容与 Mac 控制面分离

当前 VM 内容和 Mac `__harness/capabilities` 位于同一浏览器 origin；宿主入口身份还依赖 VM 返回的会话状态。固定命令、Origin/JSON 校验和互斥操作仍有价值，但无法把已失陷 VM 当作独立宿主身份凭据。

拟建立独立宿主控制面，身份凭据由 Mac 自己签发与验证。VM 只能展示只读运行状态并打开宿主确认页，不能通过 VM cookie、状态响应或自动 postMessage 执行宿主动作。

**单独换端口不足以隔离 cookie**：cookie 不以端口划分；需同时采用独立 host 名、host-only cookie 与独立认证。[RFC 6265](https://www.rfc-editor.org/rfc/rfc6265) 对 cookie 端口隔离有明确限制。

候选部署：VM 继续 `http://127.0.0.1:49226`；宿主确认页使用另一个严格校验的 loopback host（例如 `http://localhost:<独立端口>`），仅绑定 loopback，拒绝非预期 Host、Origin、跨站写请求和 framing。使用独立 HttpOnly/SameSite Strict host-only 会话、短时一次性入口凭据和 CSRF 校验；CORS 也拒绝 VM 来源。实际 host/domain、浏览器 loopback 和 IPv4/IPv6 行为需专项验收，不能仅依赖端口、CORS 或 SameSite。

Mac 原生入口生成短时一次性凭据，保存在 Mac 私有文件，不放进 VM 配置、代理请求或日志。若入口经 URL 传递，消费后立即移除 URL 参数并设 no-referrer；避免将令牌发给 VM 或第三方资源。操作仍限制为预定义生命周期动作，不新增任意 Mac shell、目录挂载或完全访问权限。[Fetch Standard](https://fetch.spec.whatwg.org/) 是跨源与凭据行为的设计依据；认证和写入校验仍需服务端执行。

验收：伪造 VM cookie、VM status 成功响应、来自 VM 页面的 fetch/form、恶意 Host、重放旧令牌、旧操作回执均不能触发宿主动作。实际宿主会话的按钮操作成功；过期/注销后拒绝；日志无令牌；VM 改进版、原版和受限模式功能分别保留。

该方案涉及 Mac 控制面，需单独实施和验收；本文件不是已完成修复、隔离证明或发布批准。
