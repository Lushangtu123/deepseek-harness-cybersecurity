# P0 规则对照验收

2026-11-03 在专用 Harness VM 中使用已安装的 Semgrep 1.182.1 和实际本地规则运行。输入为九个预先标注的合成文件。容器关闭网络，以非 root 运行并只读挂载样本与规则。没有执行样本程序。记录包含工具镜像、规则和样本哈希，临时目录及容器均已确认清理。

7 个已扫描样本包含 3 个真阳性、2 个真阴性、1 个误报和 1 个漏报。PHP 两项单独计为未覆盖。旧解析器本次返回 `complete=true`，表示有已扫描路径且无解析错误。它无法单独表达整个输入范围的覆盖率。

解析器把直接 Python eval 的 ERROR 映射为高，把 JS/TS innerHTML 的 WARNING 映射为中。以未知暴露面、未知可达性和单条规则观察作为输入时，候选排序将命中列为「尽快处理」，同时保留「待评估」。同样的排序也适用于本次误报样本，说明人工或受管核实仍需要独立证据。

## P1 接入验收条件

- 受管结果分别记录步骤是否执行完成、输入清单覆盖状态、规则命中和核实状态。将本批两个 PHP 样本登记为「未覆盖 · 无适用语言规则」，即使扫描步骤成功。
- 已扫描的 Python 文件可以保留「已检查 · 无命中」，同时明确该结论只适用于所用规则。JS/TS 的单条 innerHTML 观察保持「待核实」。复查范围缺失时保留历史发现。
- 每次启动前校验当前镜像、规则及隔离档位。缺失、变化或不可验证时记录未执行和受影响范围。S1 正式准入还需解析器上限、独立超时与重启清理验收，以及供应链来源验证。
- 使用更广、事先标注的样本验证扩展规则和核实流程，包括 PHP；依赖漏洞、EPSS 参数和真实项目效果分开校准。本批九例仅用于验证检测和结果语义，R3、全语言覆盖及阈值仍待验收。
