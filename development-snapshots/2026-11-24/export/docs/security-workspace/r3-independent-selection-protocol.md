# 普通检查 R3 选样与计分协议 v1.1

固定范围为 Python CWE-94 和 CWE-95，每类至少 20 个阳性、30 个阴性。候选是普通组合 19 条，基线是现用 16 条，仅对照原始扫描。主评分来自工具链实际输出。人工负责独立真值，人工额外核实另列。

## 来源与抽取

1. 阳性目录固定为 GitHub Global Security Advisories 中 `ecosystem=pip`、`type=reviewed`、`is_withdrawn=false`、`cwes=94` 或 `95` 的公开数据，发布日期早于 `2026-11-11T08:00:00Z`。按分页链接收齐，保存抓取时刻、每页原文摘要与固定快照。PyPA 公告用于交叉核对别名、版本和上游引用。目录标签只提供候选。真值须有维护者公告或上游修复、受影响版本的固定提交和源码位置、输入路径及适用条件。
2. 从抓取快照和固定上游依据建立别名、共享补丁、fork/镜像与根因关系表，附逐条链接及摘要；先封存关系表，再按 `SHA256('harness-r3-python-v1' + '\n' + 规范仓库 + '\n' + 家族编号)` 排序。同一漏洞家族跨包、fork、镜像与多个版本只取一例。家族编号取已核对等价别名集合转大写后的字典序首项，缺少别名时用大写 GHSA ID。规范仓库使用确认后的上游仓库，不用镜像或 fork。HTTPS 地址取小写主机名和去掉尾部斜线及 `.git` 的仓库根路径，GitHub 的 owner/repo 一并转小写，去掉查询、片段和 `.git` 远程传输格式，转移仓库以官方重定向后的身份为准。先归最具体可证类别，明确属于动态求值的 CWE-95 不在 CWE-94 重计。公告标注和根因不一致或有争议时，记录原分类与理由，留在诊断区。
3. 阴性从同一来源池中固定的公开仓库和提交取样，选择与入选阳性不同的文件、调用路径和根因家族。先按仓库及路径枚举源码可见的代码生成或求值位置，不使用被验工具筛选。对 `规范仓库、提交、路径、行、列、类别` 用同一固定种子与换行分隔的 SHA-256 排序。按顺序取证；缺乏公告不能证明阴性。阴性须固定位置及适用边界，具体核对受限解析、固定表达式、可靠输入约束或外部输入不可达的理由。阳性修复对照、训练靶场、自写例和已用案例永久只做诊断。对照未用台账冻结一份新来源池，再做逐例选择。
4. 核对台账及其已知来源引用、Git 谱系、家族和代码相似性。用目标函数的去注释、去格式 AST 形状辅助识别模板和近似复制，再由独立标注者看共享来源、路径或控制关系。每文件每类至多一例，同一执行点全局只计一次。记录每次排除的条目、判据和证据摘要。按排序选取各类首批满足条件的 20/30 个，并留存候补顺序。样本不足就报告实际可证数量及缺口，不换用已知诊断样本填数。
5. 标注者在看不到候选结果时记录真值及独立依据，封存数据集、证据索引和协议原字节摘要。执行方只获得预冻结的原始 `.py` 文件及 Python 依赖副本、文件名和 SHA-256 清单、固定规则与扫描参数、后续扫描 JSON 和绑定用摘要。真值、人工注释、公告、补丁、标签、标注表、控制组文件名与排序表由标注方保留，不放入扫描器或复核器挂载。源码本身的注释保持原字节。扫描前检验来源许可、固定提交和文件摘要，源码只作文本输入。正式运行后禁止按输出替换、重标或挪动样本；任何纠正作为历史诊断留档。调整候选后启用全新的留出样本。

## 开始条件与执行

- 先用台账中的历史样本验证两套规则的位置映射、容器镜像与参数、当前快照 v2、回执覆盖和已决证据来源。工具仅输出结构观察或不具备已决证据入口时，停在预检，报告能力和数量缺口，未使用样本不进扫描器或复核器。
- 预检通过且样本达量后，调用正式冻结入口。固定协议、原始源码与来源、两套规则、镜像、命令、评估器、复核快照、策略和运行前的台账。两套扫描使用同一内容的只读挂载，基线与候选属于同一次预先固定的比较，不对样本重新冻结。按仓库及相关依赖保持上下文，遵循现有批次 64 文件、单份 1 MiB、源码累计 8 MiB 和扫描 JSON 8 MiB 限额。超限需拆分且不能切断证明所需上下文，否则保留未覆盖。
- 原始命中对两套规则使用同一个固定规则 ID 集合 `policy.harness.python.eval`、`policy.harness.python.exec`、`policy.harness.python.request-to-dynamic-code`，并核对同一文件、行和源码摘要。第三条在 16 条基线中不存在，不构造补偿命中。规则文件逐条核对后，其他 Python 规则属于反序列化、命令、SQL、TLS 或配置等题类，不计为这两类。符合真值的代码注入路径无这些规则命中时照计漏报。保留原始列和完整扫描 JSON。缺失覆盖、错误、路径或身份不符按未知。只有候选工具链真正产生、可独立核对且绑定该例的沙箱核实产物可支持主分的已决结论。人工真值、人工补核、模型断言和结构观察不写成候选的已决回执。
- 使用同一运行前台账快照在本机与 VM 复算。启动即在单独的当期使用登记记录实际涉及的样本，完成、失败及中断都登记，下一次冻结使用更新后的台账。原冻结和评分材料继续使用原台账快照。发布复核检查标签依据、取样时间与顺序、家族去重、逐例证据和完整原始产物。评分器输出只可提交发布复核，不自动切换 R3。

## 结果

沿用现有政策的每类阈值。原始与确认检出率至少 90%，复核后误报率及 `(误确认阴性 + 未知阴性) / 全部阴性` 均最多 5%，错误排除为 0，复核未知最多 20%，且扫描覆盖无未知。此上界是对有限样本内未决项的保守计数。统计置信区间如有需要单独报告。交付逐类分子、分母、逐例证据、排除和阻断。先复审协议，再复审预检与最终交付，保留实际模型与失败回执。
