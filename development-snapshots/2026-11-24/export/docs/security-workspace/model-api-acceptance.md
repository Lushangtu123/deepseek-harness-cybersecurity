# 候选模型 API 工具调用验收

2026-11-03，使用 VM 已有 DeepSeek 配置，在临时合成项目上完成真实 `deepseek-flash` API 工具往返。模型读取既有任务，没有在调用期间启动新扫描。[结构化观察](model-api-observations.json)

## 实测与修复

| 项目 | 观察 |
| --- | --- |
| 修复前 API 往返 | 6 次模型请求、7 次工具调用；已读普通任务历史及联合结果的 2 页、10/47 条发现 |
| 暴露的问题 | `inputPolicy` 仅有内部编号，模型将 Trivy 排除类型报告为未知；PHP 缺口的字段也缺少语言说明 |
| 候选修复 | 普通任务和联合步骤新增确定性的 `coverageNotes`，解释已知 Trivy 排除策略及已校准的 PHP 数量；其他未覆盖原因保留未知，旧记录和未知策略不补造说明 |
| 修复后 API 往返 | 5 次模型请求、7 次工具调用；模型正确说明 JAR/WAR/PAR/EAR/ZIP/XML/POM 未覆盖、PHP 缺口 2 个以及另外 1 个原因未知；最大单次工具结果 5640 UTF-8 字节 |
| 续读与结论 | 同一联合任务 status、wait 和两页发现续读成功；模型明确报告只读到 10/47、报告未完成、命中待核实及整体覆盖不完整 |
| 调用边界 | 变更动作和其他项目被测试连接拒绝；调用期间新增扫描 0，合成发现保持未验证 |
| 清理 | 各次临时目录及本次拥有的扫描容器均已清理；157 项正式程序和扫描器清单的摘要前后相同 |

两次原始回答均错误地自述“6 次工具调用”，实际记录均为 7 次。修复后的覆盖说明没有解决模型自述计数问题。产品应采用执行轨迹中的确定性计数；不能把模型对调用数、预算是否耗尽或执行历史的自述当作运行事实。这次结果只证明指定流程及覆盖说明得到改善，不代表模型报告整体准确或无幻觉。

## 独立复核与最终版本

独立复核发现一项新增说明的脱敏回归：当登记的秘密仅命中说明中的 `PHP` 或 `XML` 时，既有联合回执校验会把正确的脱敏当作控制标识变化而拒绝结果。已先复现，再将 `coverageNotes` 作为可脱敏内容排除在控制比较之外。结构化覆盖字段、策略、子任务 ID、快照哈希和分页标识仍受保护，6000 字节上限保留。

最终两份聚焦测试 29/29 通过，完整插件 Node 回归通过，独立复核无剩余可操作问题。最后这项脱敏修复没有再次调用模型；在 VM 中回放了修复前保留的 6 份真实审计/联合工具结果：普通结果不变，4 份联合结果的说明可正确脱敏，标识篡改和超限仍被拒绝。回放临时目录已清理。

## 验收边界

本次采用真实注册工具的 schema、参数校验、会话绑定、执行包装、脱敏和候选 RPC/后台。仅测试连接通过 Node 模块解析钩子，将 `tools.js` 的后台导入指向临时私有套接字适配器。正式工具入口绑定正式服务的保护保持原样。

这是 API 工具循环验收，**没有启动正式 Harness 的聊天外壳或完整 Cordis 会话权限链**。因此不能据此声称已完成正式聊天预设、前端发起、批准/拒绝、会话恢复或原生模型调用验收。前端另外核对了当前构建脚本在临时副本中生成的 `client.js` 与候选文件逐字节一致，实际组件 Chrome 展示见[浏览器联调](browser-integration.md)。

初次准备阶段因临时包无法解析现有 `@deepseek-ai/dsh-tools` 而停止，模型请求为 0；临时环境清理后，补上仅测试目录的既有运行时依赖链接。没有安装依赖或替换 VM 运行时。

真实 Phishing 项目及其 95 条待验证发现未纳入本轮；候选版未部署、提交或推送。后续已补充[临时隔离环境的原生会话及外壳验收](native-shell-acceptance.md)，其额外测试围栏和正式部署边界分别记录。调用协议参考 [DeepSeek 官方 Tool Calls](https://api-docs.deepseek.com/guides/tool_calls/)，API 往返成功不替代工具实际执行及状态核对。
