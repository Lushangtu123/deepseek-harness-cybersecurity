## 四项修订

| 项目 | 修订后的行为 | 本步验证 |
| --- | --- | --- |
| 接口异常计数 | rx_dropped/rx_errors/rx_missed_errors 前后均可读、为非负整数且完全相等，才允许 complete；分析器独立重新检查 | 计数增加、负值、布尔值、缺失和不可用反例；采集器真实 main 路径的合成进程夹具 |
| 认证与未知连接账本 | accepted-key 按事件计数，分为成功 peer 二元组、控制 peer 二元组和未归属；未知事件标记 guest 时域位置。两个未归属 SYN 流单列标志、方向和条件性失败候选 | 重复事件不被 set 去重，未知事件不被归为预检；流和认证汇总计数一致 |
| 前后环境一致性 | 预检/后检 boot、记录的 sshdLimits 子集或版本不一致或缺失时失败，并保存比较结果 | 正常对照和三个字段变化、缺失的合成反例；离线用旧前后记录调用同一个纯校验函数 |
| FD-pass 正控制 | 成功 FD-pass 样本要求恰好一份 FD_META 且 descriptorSent=true | 缺元数据、缺发送、缺字段和重复元数据均拒绝，避免悄悄缩小正控制分母 |

先运行反例观察到 8 个测试方法中的 17 个预期失败，再修订。修订后 17 个套件、82 个方法通过，原有用例全部保留。正向夹具补充了新守卫要求的接口计数、发送确认及日志单调钟。C 源码、编译夹具和原生二进制与上一步完全相同；没有重新编译或扩大其权限。

## 旧数据回放的结果与边界

回放输入是 run `6db67294-7e82-4302-bcbc-248a192312a2` 的五份文件。探针/guest 数据摘要来自原 collection-summary，检查点和前后记录摘要来自原冻结审查清单；核对同一读取缓冲后解析。新分析器和 guest 辅助模块按已核对字节加载，控制器校验只从固定源码提取纯函数，不导入控制器启动 VM 操作。回放前后源文件摘要一致；原运行的 17 项冻结文件和五份数据摘要仍一致。

仍有 84 个成功标记，全部对应 guest SYN 与认证记录，38 个成功 FD-pass 正控制具备元数据和发送确认。认证事件合计 86：84 条匹配成功连接 peer 二元组，1 条匹配控制连接 peer 二元组，1 条未知，发生在 READY 前 664.359032 毫秒。未知事件仍保留未知身份；peer 二元组匹配不是唯一会话身份或 PID 的证明。

两个未归属 SYN 流保持未归属：

| 流 | guest 内观察 | 能否对应到探针 |
| --- | --- | --- |
| A | 入向 SYN、出向 SYN/ACK，随后两个入向 RST 标志摘要；无同 peer 认证类别记录 | 没有可证明的探针身份。入向 RST 只表示报文进入 guest，不能识别是原始客户端、转发层还是其他路径产生 |
| B | 入向 SYN、出向 SYN/ACK，随后双向 FIN；一条 preauth | 在失败端口也被保留的假设下，匹配一条失败端口；没有精确探针身份或根因证明 |

两条流的结束方式不同，不能归为一个已经确认的重置原因。未知流账本不使用 host/guest 单调钟相减，不用时间相近追认 direct 探针。摘要键采用 UTF-8 compact JSON array 后 SHA-256；上一轮临时本机账本使用带空格 JSON，跨编码摘要不能直接比较。

本轮只是让上述约束和分账成为可复用代码。旧数据对新守卫的回放通过，不等于新采集器在 VM 内完成了新一轮实机运行。准确转发组件/底层根因、历史侧栏首次读取同因、普通 R3 独立验收和全产品发布保留项仍开放。原始私人采集文件不进入外部审查材料或导出包。

模型提出的条件风险逐条记账，当前不伪称已经修复：

- 正控制认证事件应显式限制到 ARM 至 DONE 窗口，防同 peer 端口的旧事件被算入。本机事后核对本轮 84 个成功 peer 各一条认证事件，84 条全部在窗口内，未触发此风险。
- 新增 association→guest_sync 导入边的未来冻结执行链须验收。离线回放已按固定字节装载两模块；下一次实机的普通导入和自举信任链尚未在本步运行。-B 只禁止写 pyc，不能单独证明没有读旧 pyc。
- 环境比较只覆盖记录的 boot、sshdLimits 子集与版本，不代表完整 sshd-T 配置。未来环境不一致失败时，应补差异、清理检查和最终源码检查；不能把失败前已生成的 association JSON 当作完整验收结果。
- 账本哈希是可关联假名键，低熵 VM NAT 端口可以枚举还原，不能称匿名。序列化测试只检查字面端口未出现。
- 无关流量导致接口计数增长可能让采集保守失败；本步没有放宽守卫。
- 回放文件中 originalRuntimeSourceChanged/rawPrivateInputsCopiedToReview 是声明字段，不是自动验证逻辑。另有 scope-verification 单独核对原运行 17 项冻结文件与五份数据；外部包按白名单构建并检查，原始私有文件未复制。没有用这些声明字段冒充校验。

文件数口径：上一轮起点为 1326 个实际文件；上一轮审查归档新增两份同步诊断证据，并更新旧报告索引与 manifest，所以本轮起点为 1328。本步“未变化”比较的是这份 1328 文件基线，不是声称上轮归档没有增文件。
