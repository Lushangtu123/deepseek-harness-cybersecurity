# 普通检查：只读计划与规则对照

2026-11-03（America/Los_Angeles）。VM 候选源码；未部署、未替换运行规则、未提升 R3。

## 已接入的只读计划

`securityJoint plan mode=ordinary` 现在返回 `ordinaryPlan`：文件内容身份、范围修订、工具摘要、建议步骤、缺口和稳定计划摘要。复用已有静态预览的分类规则：源码建议 Semgrep＋Trivy，只有锁文件／配置时建议 Trivy；不支持的输入说明缺口。Dockerfile／Containerfile 现在也能进入受管文本副本。

计划仅盘点，不创建源码副本、任务或容器，不执行 Git、构建钩子或项目代码。普通启动仍因缺少 R3 而拒绝；新的计划不是执行授权。当前分类是源码／依赖／配置级别，尚未根据框架或规则覆盖把语言进一步细分。现有深度及旧联合入口保留。

盘点按目录流式读取，最多 10000 项、20 层、1000 份可接受文本。单文件最多 1 MiB，首轮累计最多读取 8 MiB，包括随后被排除的二进制和凭据材料；路径 stat 后文件增大，也受打开后大小校验约束。最终对可接受文件再核对一次哈希，额外读取最多 8 MiB。目录身份和文件读取发生变化时计划失败，不把变动悄悄改成排除。隐藏文件、链接、非普通文件、二进制及凭据材料保留排除计数；哈希身份仅针对列明的候选文本范围，不代表全仓覆盖。

## 提交时的计划核对

候选计划 v3 的摘要绑定当前项目、范围版本、可盘点文件内容、工具就绪身份、规则选择的有序步骤及请求时限。普通 `plan` 可传 `budgetSeconds`，范围 30–360 秒，默认 360 秒。普通 `start` 提交当前 `planIdentity`、范围版本、原步骤顺序和同一时限。服务端重读当前范围、输入及工具状态，复算摘要。输入、工具或时限变化需重新计划，步骤增加、减少或调序会被拒绝。旧摘要需要重新生成。深度检查和旧联合入口保留原请求形式。

复算通过后仍须经过 R3。拒绝原因按原请求编号保留，同一请求重试可查询拒绝状态，修改后的请求须用新编号。普通任务实际启动仍待 R3。

专用 VM 的私有套接字使用合成项目验证五类拒绝及同编号重试。旧摘要、步骤改动、时限改动、超过上限和 R3 拒绝均可查询。验收产生 0 个任务、0 次扫描、0 个交接副本，模型工具投影与页面投影一致。临时目录已清理，正式程序及扫描器清单摘要一致。插件回归 719 项通过。

## 固定副本与运行时限

候选普通路径在创建扫描副本时重新绑定原始文件的路径、字节数、哈希和排除计数。副本脱敏后另核对实际扫描字节。计划不匹配或复制失败时清理本次副本。排除项只计数，范围仅覆盖已列入的输入。候选普通模式仍被 R3 阻断，副本组件以独立合成用例验证。

受管 S1 静态步骤使用父任务的单调时钟截止点，继续受每步独立上限约束。容器看门狗从剩余时限中预留最多 10 秒的容器创建时间，再向下取整，仍最多 230 秒；不足 1 秒时拒绝启动容器。控制器也检查截止点，超时后到达的结果不写入发现。清理可能在扫描时限之后完成。运行预算本批覆盖墙钟时限，跨任务资源预留、累计用量和金额硬上限待接入。

## 固定样本与候选规则

[48 例静态对照](ordinary-calibration-cases.json)在扫描前固定，开发集和留出集各 24 例。[六条候选规则](ordinary-rules.candidate.json)覆盖 Python 动态求值／YAML、JS/TS 参数或 URL 到 DOM／eval、PHP 动态求值／对象反序列化。它们是独立研究子集，不是完整的运行规则替换包；安装前还须和现有额外规则合并、审查并做解析／来源／效果回归。

样本与规则由同一开发者编写，留出集不是独立第三方基准。TypeScript 只有 4 例，全部在留出集。开发集通过后没有调整规则或标签再重跑留出集。旧九例及其历史结果不改动。

**标签含义**：文件中的 `vulnerable`／`safe` 是本条静态检查的期望阳性／阴性简写。这里的 TP／TN 是与这种期望一致，不是已验证漏洞、已复现或项目安全结论。未执行任何样本，没有补齐所有版本、可达性和利用条件，因此这套集还不是 C1/R3 合格的漏洞真值基准。

- bare `yaml.load(raw)` 和别名调用只表示需要核对历史默认 Loader 的静态观察。PyYAML 6.0.2 的 `load` 必须提供 Loader，缺参会报错；不能把该样本的阳性标签直接转成当前项目存在代码执行漏洞。[固定版本实现](https://raw.githubusercontent.com/yaml/pyyaml/6.0.2/lib/yaml/__init__.py)
- PHP `allowed_classes=false` 的阴性仅用于当前对象实例化检查。它不是通用的反序列化安全证明；PHP 文档仍警告不要把不可信数据交给 `unserialize`。[PHP 手册](https://www.php.net/manual/en/function.unserialize.php)
- JS/TS 候选只把函数形参和列明的 URL hash/search 形式当来源，没有完整框架来源、sanitizer 或跨文件模型。固定 HTML 对照未命中只说明这些对照通过。[Semgrep 污点分析合同](https://semgrep.dev/docs/writing-rules/data-flow/taint-mode)

三次扫描均没有解析错误。候选包含 Python 16 例、PHP 16 例、JavaScript 12 例、TypeScript 4 例；PHP 旧规则的 16 个未扫描样本没有被算成真阴性。候选修正了这批间接 eval、固定 HTML／固定表达式及 PHP 缺规则对照。输出和命中一律保持待验证。

初次比较把两个旧规则编号的等价命中误算成漏报：`yaml-load` 与 `unsafe-yaml`、`javascript.eval` 与 `dynamic-eval`。增加明确的两项别名映射并补回归后，使用原始扫描输出重新计算上表；初始回执保留为被替代的比较错误，没有修改原始扫描或标签。任意其他前缀／后缀仍不作为等价规则。

VM 的只读计划另经真实私有套接字验证：页面投影和模型投影相同，源码改动改变两个摘要，Dockerfile 只建议 Trivy；任务、扫描与源码副本均为 0，普通启动仍返回 R3 未就绪。最大观察到的模型投影 2012 字节，没有真实 DeepSeek 调用或 Chrome 新模式验收。临时环境已清理，正式 157 项程序与扫描器清单摘要不变。
