## 接入与边界

| 部分 | 实现与限制 |
| --- | --- |
| 适用输入 | 同一副本的完整起止行列及字节偏移、文件摘要；启动前与结束后重新核对。缺失、变化或超预算显示不可用。 |
| 受管执行 | 复用固定Semgrep镜像中的Python3.12.15，镜像仅作为AST运行时。受信worker单文件只读挂载，项目文件通过有上限的标准输入传递；没有项目挂载。 |
| 沙箱 | 禁网、UID65534、根只读、capabilities全清、no-new-privileges、1CPU、256MiB、32进程、16MiB临时目录。启动前inspect核对配置。 |
| 期限 | 64个唯一调用范围／64文件／8MiB源码；worker独立4秒alarm；父进程每次调用正超时。结束清理另有三次各2秒上限，不借此启动新分析。 |
| 停止 | 强制移除、精确不存在回执及镜像正控制。创建身份未知始终标记停止未确认并阻断后续工作；服务重启回收沿用 `dsh-sec-UUID` 与security标签。 |
| 输出 | 只投影允许字段；名称身份、外部控制及字符串运行语义仍未核实。固定集合成员仍可能执行代码，不展示原字面量或可猜测的集合摘要。 |
| 汇总 | 明确区分不适用、完成、部分未匹配、截断、不可用。每个复核器保留20条，原有Python观察与新结构观察合计可能40条，使用既有报告分页。 |

## 本轮定位和修正

Terminal Claude Code实际Opus5.5 high先指出创建结果丢失、lambda作用域及零超时风险，修正后再发现同一行赋值与64行上限不一致。失败用例、初次意见与最终复核均保留在材料清单。

- 创建结果未返回有效容器ID时，即使按名称查不到容器，也保留停止未确认；create不因外部取消提前放弃结果，仍有独立超时，sudo采用SIGTERM转发。
- lambda是作用域边界，不把其参数错误归为已核对的内建名称；默认参数表达式继续按定义环境保守处理。
- 各调用计算超时后验证至少1毫秒，避免Node的timeout=0变成无限等待。关机与清理未知并发时，优先保留“未确认”。
- 赋值可以在执行点之前的同一行，校验允许行号相等；guard仍要求在执行点之前的行。超过64个不同赋值行的单个调用进入未匹配，其余观察仍保留。
- UI校验状态、计数、原任务及副本身份，拒绝把清理未知展示成已完成。固定集合只展示数量和待核实边界。

最后一次精简指定模型复核未发现所示改动的剩余阻断项。模型没有执行测试，不构成完整独立审计；其要求的最终构件重跑已另由VM记录证实。[复核台账](diagnostics/namespace-managed-20261103/review-summary.json)
