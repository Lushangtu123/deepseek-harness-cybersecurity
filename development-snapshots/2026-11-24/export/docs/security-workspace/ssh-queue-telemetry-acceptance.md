# SSH 队列诊断候选受控验收

2026 年 11 月 10 日，已归档的 R2 控制器候选通过一条真实只读 SSH 请求和一组隔离队列场景。验收器先核对已安装控制器摘要、专用 VM 配置和 SSH 信任文件元数据，再使用现有主机密钥校验，经日常队列协调，向专用回环端口发送固定的 `printf` 标记。候选在临时目录记录了一条 `completed`，返回标记准确。活动记录总耗时 103 毫秒，候选私有队列等待按毫秒舍入为 0。该等待值不包含外层日常队列的等待，也不能作为日常延迟样本。

另在独立临时队列中，用本机 Python 子进程模拟 `program-update` 占锁。等待方在 242 毫秒后超时，记录 `not-sent` 并关联到持锁方引用。等待方执行器调用次数为零。向持锁控制器发送 SIGTERM 后，本机执行子进程已退出，活动记录为 `cancelled`，主锁和观察锁均可重新取得。后续合成请求完成。CLI 读到了无传输阶段字段的旧失败样例，新超时在旧失败日志和活动记录中使用同一引用。故障和取消均在本机夹具中触发。

候选文件摘要与已审 R2 一致。实际请求通过候选运行时的临时目录接入已有 SSH 链路，日常部署仍待安排。本次验收覆盖成功读请求、受控竞争和受控 SIGTERM 收尾。历史队列超时的持锁方仍待实际采样。

Claude Opus 5.5 high 因额度限制退出。DeepSeek 官方 V4.1 Flash high 完整复核了同一份验收正文，给出本步骤有限通过，确认阻断为零。复核是静态审读。临时标记留在观察文件里也可能读不到持锁方，本轮确认的是取消后不会将它归到活动持锁方。隔离夹具结果写在临时目录退出之前，未另存本机夹具目录删除回执。真实检查以监听进程名称、用户和端口及现有严格主机密钥校验作目标约束，未独立绑定 UTM bundle 或记录主机密钥指纹。真实 SSH 的一次成功记录与日常队列的争用、取消和历史故障归因仍有不同的验收范围。
