# R3 只读保留清单与容量预览

本页记录原只读清单步骤；后续受控归档与实际准入接口见 [受控归档与容量准入](reviewer-controlled-storage.md)。原 v1 清单仍不用于迁移。

2026-11-11，本步增加 `retention-inventory`，解决私有复核缓存缺少跨任务观察与归档预览的问题。只读检查与生成 JSON 计划，不运行 Docker、sudo 或恢复命令，不创建锁或改写记录，也不执行归档/删除。读取可能更新文件系统访问时间，不宣称物理介质完全零写入。

```sh
python3 -I -B -S scripts/reviewer_snapshot.py retention-inventory \
  /home/purge/.cache/harness-review-attempts \
  --budget-mib 256 --minimum-age-days 30
```

省略目录时检查 VM 用户的默认私有缓存。目录不存在则输出空计划，保持不存在。参数是容量和年龄预览设置，不是执行配额；没有自动删除周期，也不会阻止新任务写入。成功输出报告返回 0，容量超预算或不完整也要读取 JSON 的 capacity 字段，不能仅凭退出码判断。

## 清单含义

| 分类 | 条件与含义 |
| --- | --- |
| archive-candidate | 已完成或 recovered；原记录通过格式/结果完整性校验；记录中完整清理标志成立、stage 已移除；无活动锁；达到最小年龄；已支持文件的指纹齐全，未见不安全或变化条目。只表示可进一步归档核对 |
| retain | 活动、未知、损坏、年龄不足、阶段副本仍在、文件不可读、链接/硬链接/其他用户文件、未知目录/配置、指纹预算不足或扫描不完整等情况，列出具体原因 |

每行都固定 `safeToDelete: false`，要求 `fresh-resource-check` 与 `archive-verification`。清理标志来自磁盘记录，属于 `recorded-only`；没有重新向 Docker 查询，也不是新的系统安全审计。候选不等于具备删除授权，不会把未知任务标成 recovered 或已完成。

输出绑定原目录、记录摘要、受支持日志/CID/锁文件的 SHA-256、大小、权限、属主、设备/inode 和修改时间，以及策略、生成时间和 planSha256。不会输出原始报告、日志或源码正文。未知配置文件只统计元数据，不读取内容；stage 只统计元数据，不计算内容摘要。

仅对已有普通记录打开已有锁并获取非阻塞共享锁；已有任务的 recover 会与共享锁争用，原先执行已在记录出现前持有独占锁。持锁后核对锁文件身份；基于目录 fd 相对访问，不跟随链接，不进入其他用户或不同设备的目录。目录条目和文件元数据变化时标记不完整。对同一用户/特权进程任意修改、同设备绑定挂载、文件系统虚报或扫描结束后的变化，不提供原子快照保证；以后使用计划前仍需重新核对。

## 总量与有界观察

默认最多 1,000 个顶层条目、20,000 个累计目录/文件条目、24 层递归和 64 MiB 受支持文件内容读取；限制包含扫描过程的工作量，不是缓存写入硬上限。达到限制、权限不足、活动或变化造成观察不完整时，停止给出归档候选，并标记原因。

容量按扫描到的普通文件逻辑长度统计，不等于物理磁盘占用、可回收空间或 VM 磁盘大小；硬链接可能重复计数，链接目标/外部目录不计入。只读扫描期间数据可能变化，不完整结果是已观察值，不保证是当前总量下界。`capacity.complete` 表示元数据容量观察是否完整；内容指纹预算不足可让记录保留，但容量统计仍可完整。

- `within`：完整观察到的普通文件逻辑长度未超过预算。
- `exceeded`：已观察长度超过预算；即使其他部分未知，也给出超预算提醒，不自动清理。
- `unknown`：观察不完整，且当前已观察长度尚不足以判定超预算。

真实完成任务的 CID 文件可能由 root CLI 创建。预览不会为读它自动提权；遇到不属于当前用户或不可读文件则保留。后续归档需要解决这些文件的可核对备份，不能靠遗漏它们来宣称可删除。

## 首轮复审修订与剩余边界

顶层 review 目录也须与缓存根同设备，修订后在遍历前拒绝跨设备项。预览只对已存在普通 attempt.json 的目录申请共享锁，避免在首次执行写记录前竞争其锁；初始记录缺失/非普通时只看元数据并保留，不创建文件。已存在记录的共享锁仍会与执行/恢复的非阻塞独占锁冲突，恢复可能报 lock held/active operation，应让同一任务的预览与恢复错开，稍后重试。这里没有给原 operation_lock 增加自动重试。

计划包含文件名、目录结构与元数据，真实项目计划应按私有资料保存；本轮发送模型的预览仅是合成缓存。planSha256 是自证摘要，不是签名/外部封存；未绑定工具身份、扫描上限和执行UID，后续消费者必须补齐身份与新鲜性核对。现有候选也未校验 clients 历史与全部预期日志对应，archive-verification 需要补齐。

复核校验提取改变了同时损坏结果/config 的报错优先级，两者仍在动作前拒绝。root CID 保护及全局保守策略可能让大缓存全部 retain；分批续扫/可信备份/容量准入未实现。ctime和额外打开标志、更多边界样本仍在后续账。原生年龄条件使用0天，默认30天用单元测试时间注入覆盖；CLI只核对容量/分类，未逐字段核对reasons/files。

最终复审补记：缺记录目录可能仍在初始化，不能直接视为孤立残留；容量 complete 只表示没有观察到枚举/元数据变化，不表示系统静止或没有后台任务。两次 record stat 之间首次记录出现时，可能出现 missing-lock 原因误标，该行仍因 record-unavailable 保留；此精度与额外errno测试继续记账。普通文件挂载的设备收紧仍是后续项，同用户/特权任意变更不在原子快照保证内。root CID 即使0644可读，也会因非当前用户属主而保护，不以不可读概括。

新增分支的跨设备/预记录/非普通记录由Mac/VM中的mock控制覆盖，没有声称做了真实挂载或并发调度验收。Mac原始测试日志没有内嵌源码摘要，绑定依赖实际捕获的命令和固定字节；VM结果结构中包含源码摘要。两者都不是外部封存或独立安全审计。
