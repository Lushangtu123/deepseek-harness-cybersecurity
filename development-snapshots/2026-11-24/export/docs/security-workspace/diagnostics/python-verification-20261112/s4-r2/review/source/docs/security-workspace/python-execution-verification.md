## 调用计数与规则准确性

新任务在开放模型网关前显式初始化计数。预算文件绑定任务、限额及协议；恢复读取原计数，缺失、损坏或身份不符均拒绝转发。预留使用独占文件锁，先持久化计数再转发，结果不明不退款。测试使用合成网关，不启动付费 PentAGI 任务。

Python 适配器、Node 汇总及页面只将协议 1 且状态可核对的整数计入已知次数。缺少信息返回 `modelCalls: null`；任一步未知，总次数也未知，可单独显示已记录小计。历史数值标为原记录、未核对，不重写原回执。新任务在第一份回执之前准备失败，仍可能留下需要人工恢复的孤立目录；此问题保持登记，不会因此自动转发或归零。

`validDeepSemgrepProfile` 原来就逐字段匹配固定合同。“只校验形状”的旧意见不成立。本轮只补充模式、摘要、条数和额外字段反例，未添加重复验证逻辑。

## 隔离、证据和限制

核实器执行固定的完整原始源码，支持 Python 单函数入口和 Flask 进程内测试客户端。固定入口配方声明输入属于非信任数据；按设计接受 Python 代码的接口不适用此合同。不启动对外服务器，不替换 `builtins.eval/exec`。依赖来自精确版本和上游摘要固定的独立目录，不升级日常依赖。

| 项目 | 当前固定限制 |
| --- | --- |
| 镜像 | `sha256:9479bc40712c72437ee2630d947c102cf0c1cd5200ec038026272427925b82e7` |
| 解释器 | CPython 3.12.15 |
| 身份与文件 | UID/GID 1000，根文件系统及唯一源码 stage 挂载只读 |
| 网络与权限 | 网络 none，capabilities 全删除，no-new-privileges，无特权、凭据或 Docker socket 挂载 |
| 资源 | 512 MiB 内存及同额 memory-swap 上限，1 CPU，64 进程，32 MiB 临时空间 |
| 请求 | 每点最多 4 输入、每输入 5 秒、整点 30 秒、报告最多 256 KiB |
| 批次 | 主诊断批次串行且最多 8 点，拒绝边界对照逐个提交，CLI 一次只提交一个点 |

15 个真实容器的 inspect 记录核对了这些配置。验收还核对了私有 stage 中的源码与清单逐个一致，并确认清单外的合成源码没有进入挂载。容器采用 Docker daemon 默认 seccomp。Python monitoring 提供条件性观察，同进程代码的防伪仍是能力缺口。

确认同时核对真实内建调用对象、指令位置、完整调用范围、`pointId`、探针程序及返回/标记原值。普通回显或“调用过 eval”不成立。排除仅接受类型和控制流可以证明的单引号字符串或固定安全字面量集合；未触发不是排除证据。页面输出、stdout 和模型判断不能直接进入工具主分。

为避免同进程伪造日志，本轮将执行能力限定在 worker 内置的 6 份已审阅源码摘要（含依赖的项目 helper）。未知源码在导入或执行前拒绝。增加新源码必须作为工具代码变更重新测试和审查，项目、计划或请求不能自行添加允许摘要。这个限制使当前版本停留在预检阶段；正式盲测需要先解决任意项目的可信观察问题。

## 接口与兼容

| 数据 | 当前版本与行为 |
| --- | --- |
| 静态快照 / 数据集 / 静态回执 | 保持 2 / 3 / 3 |
| 核实快照 / 核实回执 | 独立版本 1 |
| 新冻结 / 运行记录 / 质量报告 | 4 / 4 / 8 |
| 历史 v2、v3 评估 | 继续诊断读取，缺少核实合同不能获得新正式资格 |
| 人工补核 | `humanSupplement` 单列，不替代工具主分 |

通过固定工具目录的 `scripts/reviewer_snapshot.py` 使用以下接口。摘要参数必须取自实际冻结材料；例子中的大写名称是占位符。

```text
freeze-verifier STATIC_BUNDLE STATIC_SHA DEPS LOCK_JSON CONTRACTS_JSON DEST
verify-execution BUNDLE EXPECTED ROOT MANIFEST SCAN REQUEST DATASET_SHA FREEZE_SHA --attempts-root PRIVATE --timeout 30
status ATTEMPT
recover ATTEMPT
```

Python 入口为 `verify_execution(...)`。`REQUEST` 仅接收 `version: 1`、固定 `contract`、完整 `point` 和冻结的 64 位十六进制随机 `challenge`。不接收用户代码、setup hooks、自定义探针或可执行模板。Flask 模板仅允许工具定义的固定文本。

快照绑定固定工具代码、静态三模块闭包、依赖树、配方、解释器、镜像、策略与源码允许摘要。依赖锁须与工具附带的 [固定版本与摘要](../../scripts/verifier-dependencies.lock.json) 一致。依赖通过目录 FD 和 no-follow 打开，普通单链接文件只读取一次，哈希和实际返回的是同一缓冲区，并核对读取前后文件身份。链接、读取时修改、冻结后源码或依赖变化均拒绝。

核实复用已有容量准入、任务锁、超时、容器与客户端所有权核对和清理。`status/recover` 查询原任务及回执。回执绑定源码、执行点、请求、数据集及冻结、运行身份、原始报告和清理结果。评分器核对实际报告、请求、清单及扫描字节，并与当前工具附带的核实器和依赖锁比对。缺失计划回执会产生明确的覆盖阻断。早期冻结与当前核实器不一致时，可用对应的历史工具诊断。
