# 受控归档与容量准入（离线 VM 候选）

本阶段增加协作式启动准入和受控归档维护，仅用于 VM 候选及隔离验收。日常 VM、宿主权限和 R3 资格不变。此文档的接口已实现；最终隔离 VM 结果与外部复审在结构化记录中单独报告。

## 容量准入

`run` 在创建任务目录、stage 和 Docker 客户端之前登记预留。默认活动缓存预算 256 MiB，每任务预留实际冻结代码/输入字节加 96 MiB，文件系统另留 512 MiB，并计入其他未结算预留。活动任务计预留，终态任务计普通文件实测逻辑长度；无法可靠核对时拒绝新任务，不终止正在运行的任务。

容量锁在任务锁之前，均非阻塞；锁忙返回可重试。执行和恢复先退出原任务锁，再结算预留。新准入会先核对已有预留；未知、缺记录、损坏和不完整状态继续保留，年龄和 PID 退出均不是释放证据。已知准备失败在当前控制器能证明引擎未触及、同步写入已退出时，先保存正向证据；后续核对原目录身份及记录/CID 缺失后才释放，残留字节仍保留并计数。

这是协作式启动准入，不是操作系统硬磁盘配额。目录块、Docker 自身占用不在逻辑缓存计量内；磁盘余量另外检查。重复恢复可能增添日志，不提供运行期间硬限制。断电恰好发生在登记预留与准备失败证据之间时，未知预留会保留；对账必须查询原任务，不能删账本或仅凭超时放行。

策略和账本位于缓存同级 `.harness-storage-<缓存路径摘要>/`，独立于活动缓存。策略首次初始化后固定；显式 `run --storage-policy JSON` 仅接受完整、当前 UID/规范缓存路径匹配的工具策略（可调整预算和最低余量），不是项目提供的执行模块。默认运行保持 256/512 MiB。维护对账可能初始化私有控制目录，属于写操作。安装升级前应保留原工具与账本并先对账；没有自动策略迁移。

## 快照和旧记录

新冻结快照为 v2，绑定 `reviewer_storage.py`、启动器、三个复核模块和镜像不可变 ID。Python 只执行安装目录固定路径、摘要匹配且导入闭包通过的存储模块；bundle 只作字节核对。项目、计划和模块路径参数均不能指定执行代码。归档使用固定 libc 无覆盖重命名原语；不加载项目动态库。

旧快照和旧清单可用于只读诊断，不能执行新任务或搬迁。Python 旧快照诊断优先提示重新冻结；Node 同时保留形状合法快照的身份不匹配诊断。质量报告仍为 v6，新增 `reviewer-snapshot-legacy-storage-unbound` 门槛；历史回执格式未改。新冻结任务必须使用当前 v2 字节，历史完成结果不回写。

## 归档命令

以下在非 root 的 Linux VM 中执行；缓存需是工具的私有目录。计划包含路径/文件名元数据，应以 0600 私有保存。

```sh
CACHE=/home/purge/.cache/harness-review-attempts
python3 -I -B -S scripts/reviewer_snapshot.py storage-reconcile "$CACHE"
umask 077
python3 -I -B -S scripts/reviewer_snapshot.py archive-plan "$CACHE" \
  --attempt-id 0123456789abcdef0123456789abcdef > archive-plan.json
python3 -I -B -S scripts/reviewer_snapshot.py archive-apply "$CACHE" archive-plan.json
python3 -I -B -S scripts/reviewer_snapshot.py archive-status "$CACHE" TRANSACTION_ID
python3 -I -B -S scripts/reviewer_snapshot.py status "$CACHE/review-ATTEMPT_ID"
python3 -I -B -S scripts/reviewer_snapshot.py archive-restore "$CACHE" TRANSACTION_ID
```

省略 `--attempt-id` 时有界观察最多 1000 个顶层项，一批选最多 8 个终态任务；指定 ID 可对大缓存逐批维护。新 v2 计划绑定工具版本/源码摘要、UID、策略、限额、缓存和源目录身份、完整文件指纹，默认 15 分钟有效。旧 v1 清单只诊断。新受控归档允许已核对的终态立即进入回收区；原只读预览的默认 30 天年龄设置不改。

计划源读取和一次 apply 的累计内容读取分别最多 64 MiB。apply 预算包含两次源指纹读取、压缩文件读取及解压成员核验；估计时为多遍核对和头部预留，因此每批实际独有源数据可能明显少于 64 MiB。每任务最多 20000 个条目，已知日志编号最多 9999；仅完整唯一客户端记录（最多 128 条）可归档，已截断历史任务保留。达到限制保留任务并缩小批次，不省略证据。空间检查还为压缩包、事务、逐文件块和写入暂存预留余量。

只接受已确认资源清理、stage 移除、完整原记录与日志清单一致的终态。文件需是普通单链接文件；链接、特殊文件、跨设备、未知配置/文件、活动锁、未知或损坏任务保留。root CID 的精确例外只适用于可读的普通单链接 CID 文件、64 个十六进制字符（可带换行）且与记录完全一致；不通过 sudo 读文件或改变属主。

## 事务和恢复

维护先取容量锁再取任务独占锁，重新核对指纹。Docker 的名称、CID、任务标签和源客户端标记均需实时只读查询为空；查询日志写入独立事务目录，不调用删除资源的清理函数。然后生成 0600 的私有压缩归档，重新读取校验所有成员、大小、权限和 SHA-256，再核对原指纹并在同一文件系统用原子无覆盖重命名迁入私有回收区。

事务目录保存每步进度，外部索引绑定原路径。重复 apply 查询同一事务，即使计划已过期也不会重新探测、分析或搬迁。中断后运行 archive-status；迁移前源仍在会记录 not-moved，迁移后原路径缺失且回收目录/归档完整则完成原事务。两边都缺失/同时存在或无法核对时保留未知状态、事务和索引，不盲目重做。

原路径的 status/recover 会返回 archived 或 archive-pending，以及事务编号；recover 指向 restore-required-no-analysis，不重新启动复核。restore 只回原路径，原路径已存在（包括空目录/链接）就拒绝覆盖，检查归档、容量、路径和原字节。回收目录尚在时原子搬回，保留原文件身份；若操作者已移除回收副本，则从已核验归档逐个恢复固定成员，不使用 extractall，归属当前 VM 用户、文件 0600，保留原字节；不自动 chown/root。新复制文件身份可能变化，事务记录恢复指纹。部分复制无法证明完整时保留暂存和事务，不覆盖或删除。

完成记录、历史 result 和完成回执不重写，也不生成新的分析回执。恢复进度独立于原任务。回收副本至少保留 7 天；不完整或损坏的事务在 `transactionUnknown` 中保留报告。期满 `storage-reconcile` 仅给出 `cleanupCandidates`，`deleteEnabled:false`、`safeToDelete:false`，不会删除回收目录、归档、任务或容器。本阶段没有删除命令或定时清理。

非阻塞锁忙和容量拒绝输出 storage-blocked JSON（exit4）；格式/身份/指纹异常拒绝并保留原事务，可用计划中的 id 查询。旧原路径恢复要求下一步是查询/恢复原任务，不应创建新分析任务。文件系统和同 UID/特权任意篡改不提供原子快照保证；逐遍核对、私有目录与合作式锁控制工具自身并发。

日常 169 项程序、42 个项目库逻辑、关键配置及固定运行时入口摘要前后一致；没有核验完整运行时目录树。指定 Claude 审查完成了前段步骤，后续因周额度失败按持续授权转交官方 DeepSeek V4.1 Flash high。长度截断和不完整响应保留为失败，不计通过；完整报告意见逐条核对、确认问题补回归修复后复审。最后验收证据与独立收尾字节摘要核对已关闭，无本阶段已确认阻断。辅助一次性验收脚本的重跑记录写入顺序等低优先级边界单独记账，不把它当作产品幂等 API。
