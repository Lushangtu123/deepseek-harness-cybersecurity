## 已落地的代码边界

`package/lib/redteam/personal-workspace-contract.mjs` 提供纯计划预览与状态派生，不导入执行器、数据库或网络模块，不注册新 RPC。当前入口、默认预设、既有发现和运行数据库未迁移。

计划只选择存在适用输入的静态步骤；普通预览需要工具与 S1 均达 R3，深度静态预览至少 R2。就绪元数据只用于预览，不是执行授权或运行证明。计划摘要绑定输入、范围修订、工具镜像和策略摘要；缺少适用工具时明确记录缺口。Python 的 Bandit 只有登记了补充覆盖时才加入；Kali、REA、PentAGI 不预先启动。

任务分别表达执行、结果收录、覆盖与清理。问题分别表达检出、处置与修复进度；状态显示与排队谓词保持一致。接受风险等处置的当前有效性由后台计算，未提供有效性时不当作有效抑制。工作流不自动生成 VEX。

### P1 静态扫描启动核验

VM 候选源码对 Semgrep 和 Trivy 在分派前再次核对本地镜像和各自的规则或离线数据库身份，并检查 Docker 的内置 seccomp、cgroup v2 及 CPU、内存、交换空间和 PID 限制能力。分派复核失败时保留原请求的失败回执，说明范围未检查。静态容器的临时目录禁止设备文件和执行，限制内存加交换空间，并移除无关任务目录挂载。ZAP 仍由独立的本地 HTTP 路径运行。

专用 VM 使用临时模块完成本机正反验收：两种扫描器的当前身份通过；改变接收时身份、规则摘要或数据库摘要均被拒绝。临时模块已清理。该回合只验证启动门槛，候选源码未部署。运行期独立清理、解析边界、资源在核验与绑定挂载之间的替换窗口及上游来源验证仍待闭环。

静态扫描的容器入口现有独立 230 秒时限。到期时入口以 124 退出，由容器 PID 命名空间终止剩余进程并由 Docker 自动移除。控制器在线时记录超时并丢弃该次输出。此前验证的启动门槛、控制器取消路径仍适用。该时限从容器入口启动起算，Docker 启动卡住或服务重启后的任务对账仍需单独验收。

静态扫描将 Docker 创建与启动分离。创建调用限时 10 秒，只有取得完整容器 ID 才能启动；创建结果未确认时记录未启动。取消或启动失败按 ID 清理。扫描服务重启时先核对固定命名空间，清理已创建和运行中的容器，再对账中断任务。VM 探针验证启动附加返回超时码 124，清理两类容器后旧 ID 无法启动。创建请求在 Docker 侧延迟完成时仍可能留下未启动的容器，下一次服务重启会重新清理；本轮未对运行中的服务做故障注入。

新增独立扫描服务重启回归。测试经私有 Unix 套接字启动合成扫描，强制终止测试服务，再从同一 SQLite 状态重启。监听前完成对账；已结束任务保留，中断任务标为结果未确认。原请求重复提交只返回旧任务，改写同一请求被拒绝，新请求仍能执行。测试在专用 VM 的临时目录运行，与此前 Docker 容器清理探针分开验收；正式服务尚未部署或重启。

静态扫描结果在解码和递归脱敏前检查 UTF-8 JSON 结构。保留 8 MiB 扫描结果上限和 64 KiB 传输余量，并限制 64 层嵌套、25 万个结构标记和单个 JSON 字符串的 256 Ki UTF-16 代码单元。超过结构上限或格式无效时，任务失败，保留诊断，且不写发现、覆盖结论或对比快照。专用 VM 的合成用例覆盖正常转义、深嵌套、大数组、长字符串、超大传输、无效 UTF-8 和畸形 JSON。范围限于 Semgrep/Trivy 到控制器的 JSON 输出，扫描器内部输入解析、压缩包、XML 和其他报告格式仍待单独验收。

Trivy 普通静态入口暂用固定后缀策略排除 JAR、WAR、PAR、EAR、ZIP、XML、POM，覆盖标识随策略变更，演练台和报告标注缺口。Maven POM 依赖在此路径暂不覆盖。专用 VM 以当前 Trivy 验证根目录和嵌套目录、混合大小写后缀、带外部引用的 XML、嵌套 JAR 和正常依赖对照。Semgrep 当前实际规则下，XML 和 JAR 未出现在扫描路径中，Python 正常命中。此验收只覆盖当前规则与识别到的后缀，内容伪装、受限解包及 XML 专项检查仍未验收。Trivy 的目录遍历顺序见[固定版本源码](https://github.com/aquasecurity/trivy/blob/v0.76.1/pkg/fanal/walker/fs.go)。

Semgrep 分派时以有界读取取得规则字节，再与运行清单摘要核对，通过后在私有任务目录以独占创建方式写入只读副本。容器计划只挂载该副本，扫描结束后清理。专用 VM 对照在容器启动前替换原路径，容器仍只执行已固定的原规则。摘要不匹配或规则路径为符号链接时拒绝启动。此保护针对原规则路径的替换；同账户主动篡改任务目录、服务崩溃后遗留副本的回收，以及 Trivy 数据库挂载的固定仍待单独处理。

Trivy 分派时在私有任务目录为约 1.66 GB 的只读数据库建立同文件系统硬链接，并对该链接所指文件重新核对大小与摘要。元数据独立核对并复制，容器只读挂载固定目录。这样可抵御数据库更新时原路径的替换，同时避免每次复制整库。数据库具有写权限、无法创建链接或摘要不符时拒绝启动。硬链接仍指向同一文件，无法抵御有权修改该文件内容的主体主动原位篡改。

正常结束时清理固定输入。服务启动先核对容器清理，再按中断任务的原 UUID 回收固定的 Trivy 数据库链接和 Semgrep 规则副本。回收仅处理已知文件名，保留任务中的其他文件。专用 VM 以真实离线库的临时别名做路径替换并运行 Trivy；正式库和工作台未替换。

### 上游来源与发布者核验

[来源核对记录](upstream-evidence.json)保存了固定上游索引、ARM64 清单和配置的摘要核对结果。Semgrep 的 15 层、Trivy 的 4 层均与 VM 镜像逐层一致，九项已检查的执行配置一致。导入后本地镜像 ID 与上游配置摘要不同，仍需在各自命名空间中分别核对。

离线库核对链为 GHCR 固定清单 → 缓存压缩层 → 解包后的数据库字节 → VM 实际文件，四段对应一致。此库的上游建议更新时间已经过去，来源一致不能说明漏洞数据覆盖最近的公告。

Trivy 0.76.1 的固定上游索引已通过 Cosign 3.1.4 验证。证书身份绑定到官方发布工作流和 v0.76.1 标签，证书链和透明日志验证通过，两条签名声明均绑定该摘要。将证书身份改为 v0.76.0 后，同一镜像被拒绝。VM 的 DNS 无法解析 GitHub，验证改用宿主的临时校验程序，按官方不可变发布资产的 SHA-256 核对后运行并清理。Semgrep 和 Trivy DB 仍仅完成内容核对。[Trivy 签名核验说明](https://trivy.dev/docs/dev/getting-started/signature-verification/) · [Trivy 数据库发布位置](https://github.com/aquasecurity/trivy/blob/main/docs/guide/configuration/db.md) · [Semgrep 官方镜像说明](https://semgrep.dev/docs/update)


更新准入的证据应绑定候选版本、上游不可变索引摘要、官方签发者与工作流身份、索引中的 ARM64 清单以及导入后的本地镜像 ID。发布签名验证失败、无法复现或与候选身份不一致时保留现用版本。离线库需要单独的发行证据，现有镜像签名只覆盖 Trivy 镜像索引。候选更新器现已加入默认拒绝的发布者准入。Semgrep 按候选本地镜像 ID 与版本比对，Trivy DB 按上游清单与压缩层摘要比对。两类资源都还没有已验证的准入项。启动器检查和既有事务恢复可用，缺证据的更新在执行前停止。Trivy 程序镜像当前没有常规更新入口，其上游签名验收记录未被写成其他资源的准入项。
