# 字符串条件证据交付与质量门槛修订

2026-11-03，日常专用 VM 的六项程序变动完成切换，165 项程序与导出源码摘要一致。包版本标识沿用 `1.1.77-personal.11`，本批以程序清单和归档摘要区分。原 165 项程序保留在 VM 私有回退目录。[结构化验收](string-evidence-acceptance.json)

## 用户可见结果

在演练台「安全审计」的联合安全审查卡片，完成受管 Semgrep 深度步骤后，点击「查看 Python 证据」可见三类补充观察：白名单条件、字符串条件、跨文件数据流。每项均显示原位置及相关条件或执行点行号，并标为待核实。下载的联合 JSON 报告包含同一批证据。

这些观察帮助核对扫描命中，不会抑制原发现、改变严重性或把问题标为已确认。字面量白名单、字符串方法和跨文件导入的运行时语义仍需核实。当前深度工作区入口仍只接通首批 S1 静态步骤；本批没有完成所有深度能力。

## 复核与修复

按用户要求通过 Terminal 调用 Claude Code，只发送固定源码快照，禁用工具与 MCP，没有使用权限绕过。多轮复核发现并修复：

- 同一行同时出现 `eval` 与 `exec` 时，行号证据可能关联到错误调用。现在要求关联语句跨度内只有一个动态执行调用，批处理与 Node 投影再次核对明确规则和实际执行函数。
- 字符串条件可能来自全局或闭包值。现在要求条件之前紧邻一次局部单目标赋值，函数内只有该次写入，并排除 global/nonlocal；这仍不证明输入来源和实际字符串类型。
- 离线质量核对的已决样本误报率可能被未知阴性稀释。加入未知阴性的保守误报上界；同时补齐命中源码/语言/CWE/行号、证据样本/结论和运行/冻结/台账的摘要绑定。

质量门槛只生成离线复核报告，所有尝试的台账登记和冻结摘要的事先保存仍需受控运行器或人工发布复核，不构成签名证明。[质量门槛 v2](review-quality.md)

复核针对这些固定文件及修复范围，不是全仓独立安全审计。最后一项行号测试隔离修正已在 Mac/VM 测试通过，未在仅测试变动后再次做代码复核。交付记录另通过 Terminal 调用 Opus 5.5 high 检查；它指出旧版逐例明细未更新等记录问题，本批已按原始回执重新生成。后续普通复核继续默认 high，深审使用 xhigh。

## 实测与数据保护

固定 OWASP 开发集 53 例原命中全部保留。收紧后 9/33 个阴性获得字符串条件观察，20 个阳性均无此观察；旧版另外 13 条观察撤回为未知。不是误报减少或安全结论。历史 22 条记录保留为前一候选结果。

Chrome 的日常原生深度按钮发起一次独立本地合成任务，Semgrep 扫描 4 个文本文件，得到 7 条命中及 3 条补充证据。弱化的字符串条件没有生成字符串证据。发现、文件、排除、诊断、产物五节逐页读取后，与下载 JSON 逐项一致。补拍可见证据区域时复用原任务，没有再次扫描。首次使用声明沿用用户此前明确接受的授权，测试浏览器结束时关闭。

验收后 39 个既有项目数据库的逻辑摘要匹配，受保护配置和扫描器清单逐字节匹配，日常活动项目已恢复。新合成项目保留供复查；只有一个联合任务和一次扫描，没有向普通发现表添加记录。7 条命中与 3 条证据全部待核实；容器及临时扫描输入均已清理。本次没有真实 DeepSeek 模型请求。

测试通过：745 项插件、324 项 Python、Mac 与 VM 各 20 项质量门槛、VM 24 项 Python 证据测试，以及前端可重建一致性和部署保护回归。两组已用样本的回顾性质量回放在 Mac/VM 逐值一致，仍被判为 blocked。回执中的 external 是此前 Django 4 例，historical 是此前 OWASP 53 例；两者当前均不是新的独立验收。

## 部署中断记录

首次切换在停止服务后的数据库物理摘要保护处被拦截，在程序替换之前恢复原服务。只读复查确认原程序、39 个旧数据库的逻辑内容、配置和扫描器清单均匹配。逻辑基线是在首次部署停止服务前另行只读采集的 `iterdump` 摘要，汇总摘要记在结构化验收的 `deploymentDiagnostic.logicalBaseline`，不是拿停止后的数据自比。转储覆盖 schema 和行数据，不声称覆盖数据库头 PRAGMA 或所有旁路文件。

旧部署辅助脚本按数据库主文件的字节摘要比较；SQLite WAL 回写可以在逻辑内容不变时改变该摘要。以真实临时 SQLite 数据库重现了这类误拦截，并加入能区分「只回写」与「实际新增数据」的回归。部署辅助脚本改为比较只读逻辑转储摘要，配置和扫描器清单继续比较字节摘要，重试成功。

首次失败没有保存具体变动文件的前后物理摘要，不能确定是哪一数据库或将 WAL 断言为唯一写入原因。失败记录与暂存包保留；第二次切换记录了停止前后摘要。

## 仍未完成

R3 独立效果准入仍缺足量、有漏洞位置和适用条件依据的独立样本。候选 19 条规则组合未安装，普通检查未因此放行，候选质量阈值尚未成为生产策略。现有真实项目的待验证发现没有迁移或自动核实。

Python 补充证据仍采用有界批处理，最多 64 份 Python 文件、64 项核对和 8 MiB；不支持的路径或超限可能导致整批证据 unavailable。原始扫描结果仍可读取，不能据此宣称完整复核覆盖。广泛跨文件分析、运行时核实与后续产品阶段仍需继续。
