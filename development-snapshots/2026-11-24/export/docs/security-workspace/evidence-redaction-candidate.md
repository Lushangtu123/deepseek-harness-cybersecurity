# 证据闭环与源码脱敏候选

本轮只处理综合复核 POL-F1、POL-F2、POL-F4。候选源码包含 172 个程序文件，日常 VM 仍为已验收的 169 文件 / 16 规则部署。本轮没有安装候选、发布或推送；R3 和完整工作区仍未通过，真实项目的既有待验证发现保持原状。

## 行为变化

- 引用证据与核实申报分别记录。只有 `upgrade` 写入的精确关系及匹配原生回执才闭环其对应申报，不再把其他支持引用一起计为已核实。关系和 observed 记录在同一个 SQLite 保存点内写入。
- `derived` 至少引用一条同项目、有原生核实关系的 observed 记录。推导结论仍计入待核实，需要自身匹配的回执才能闭环。模型只能直接填写 operator-input / subagent-report，强来源标签由可信路径写入。
- 旧证据行、内容哈希和引用顺序保留。旧库缺少精确关系的申报保持待核实；重新提交同一条申报及匹配原生回执可补关系，并复用已有 observed 行。迁移不会从支持引用猜测核实关系。
- 结构化展示、JSON 副本和 Python AST 共用敏感命名规则，补齐前缀、驼峰、SECRET_KEY、GITHUB_TOKEN、DB_PASSWORD、privateKey 等常见形式。普通 public_key、token_count、password_length 和 has_secret 布尔状态可读。
- Python 覆盖下标、嵌套元组、注解、命名表达式和默认值；保留环境读取的键名。无法可靠对应的敏感解包拒绝复制。解析子进程只处理标准库 AST，不执行项目代码。
- 实际工作台源码读取先对完整文件结构脱敏，再按脱敏 UTF-8 字节分页；最后仅再次去除已登记值，避免重复文本替换破坏结构或偏移。原项目文件只读。
- JavaScript 比较运算符不当成赋值。复杂敏感表达式、后备值、拼接和类型注解缺乏可靠结构边界时拒绝复制；不保留未遮盖的表达式尾部。JS/TS/JSX/TSX 使用该保守边界，JS 额外核对语法。

## 验证与限制

测试以合成凭据和内存/临时数据库进行，涵盖引用误闭环、伪造来源、跨项目支持、精确回执重放、事务回滚、边界容量、源读取与工作台分页，以及正常字段和源文件不变。外部模型意见仅作为复核输入，不算漏洞已确认。

敏感命名仍是启发式规则，不是任意秘密发现器。动态来源、任意混淆、其他语言的完整 AST、复杂 JavaScript 表达式的结构脱敏仍有覆盖限制。保守拒绝复制应显示为读取/覆盖缺口，不能变成“未发现问题”。数据库自身被可信管理者直接改写不在模型工具来源校验的威胁边界内。

详细执行结果见同目录 `evidence-redaction-results.json`；候选和日常部署状态分开记录。
