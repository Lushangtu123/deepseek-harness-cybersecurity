# 候选收录：完整位置与受管副本摘要

2026-11-03（America/Los_Angeles）。本批候选源码为166项程序；日常 VM 仍运行此前165项程序，16条规则没有替换。没有迁移项目或修改原有发现。

## 本批变化

Semgrep 的JSON提供起止行、列和字节偏移。[官方字段说明](https://docs.semgrep.dev/semgrep-appsec-platform/json-and-sarif)。候选解析器把这些字段保存为 `scannerSpan`，但只在完整结构有效、路径及规则标识没有因脱敏而变化时保留。原始源码片段、metavars和修复文本不收录。

受管联合扫描结束后，新模块 [personal-security-source-location.mjs](../../work/harness-purge-improved/package/lib/redteam/personal-security-source-location.mjs) 核对：

1. 副本清单的路径、摘要、大小、布尔脱敏标志和快照编号。
2. 实际副本是普通文件，路径未链接，长度及SHA-256与清单相符。
3. 起止行列与绝对字节偏移都指向同一份UTF-8副本，位置不在多字节字符内部。

成功记录 `sourceLocation.state=bound`，保存副本路径、快照编号、摘要、字节数、脱敏标志及起止位置。**bound只表示副本字节范围匹配，不证明扫描结果的来源、该范围是AST调用、实际执行或漏洞。** 它不表示原始未脱敏文件可使用相同偏移。若其他文件的偏移恰好符合副本行结构和长度，单靠这项核对无法区分；实际扫描来源仍依赖受管runner与固定输入身份，后续AST复核另作核对。

缺字段、清单无效、源码变化、符号／硬链接、读取预算不足或范围不匹配时，记录明确的 unavailable 原因，保留原警告。没有从旧“文件:行”推算列或偏移。部分绑定的汇总为partial，全部不可用时为unavailable；该汇总不改变扫描器的执行状态或正式处置状态。

每个文件只读取一次，单文件最多1MiB，按清单大小预留总8MiB读取预算，失败读取也计入预留额度；清单最多1000文件、结果最多2000条。现有解析器及文本补查先限制2000条，超限的自定义runner不是受支持输入。副本创建器已有同样的单文件、文件数及总大小限制。

## 持久化与报告

新位置只写入受管联合发现的JSON记录；随后进入联合任务数据和分页结果。已绑定位置以快照、副本摘要和完整范围区分，因此同规则、同文件、同一行的不同调用不会被合并。未绑定及历史记录继续沿用原来的按行分组，不补造精度。

绑定对象及结果数组不可变，后续Python证据收集不能替换它们或追加伪造记录；模型输出的控制字段核对也包含 `sourceLocation`，避免脱敏改写摘要或坐标后仍被当成原标识。

旧 `security_finding` 表、指纹、复测流程和比较快照保持原逻辑。比较快照仍按行，不作为新复核器的精确位置来源。本批没有数据库列迁移，也没有自动调整状态、优先级或风险结论。

## 验证

- Mac和VM均通过**759项插件测试**，其中11项位置专项包括同一行双调用、实际持久化／分页／重读、元数据防篡改、同长度源码变化、链接、无效清单及脱敏控制字段。
- 实际受管脱敏对照在两个调用前登记合成敏感值：按副本计算的范围绑定到副本摘要，`copyRedacted=true`；原文件摘要不同。**本对照**的原文件偏移超过缩短后的副本范围，因此绑定失败，警告保留，记录没有原偏移或敏感值；这不是对所有来源混用的检测保证。
- VM临时环境回放两套原扫描的21／21条记录，以及Unicode／CRLF／制表符的6条记录。共3次fixture runner调用，**0次新扫描、0次模型调用**；两套旧来源重复，只计同一批开发材料。

- 165项日常程序、40个数据库逻辑摘要、扫描器／规则清单匹配，临时候选目录及临时事实库已移除。逻辑摘要不声称SQLite旁路文件零写入。
