# R3 复核器输入与类型边界

2026-11-11，本步处理 N3/N4：启动器过去允许单个源码/清单 2 MiB、扫描文件/源码合计 16 MiB，实际批量复核器只接受 1 MiB 和 8 MiB；另有 Python `True == 1`、`1.0 == 1` 导致的版本类型混用。仅修改离线候选启动器及其测试，三个受固定摘要保护的复核模块、Node 质量门槛、扫描规则、阈值和来源台账保持原字节。

## 固定合同

| 对象 | 上限或校验 |
| --- | --- |
| 单个 Python 源码 | 1 MiB，UTF-8 |
| 输入清单 | 1 MiB，UTF-8 JSON 对象 |
| 单个扫描导出 | 8 MiB，UTF-8 JSON 对象 |
| 源码合计 | 8 MiB；1–64 个受支持路径 |
| 复核器模块/客户端 stdout | 各自沿用 2 MiB 限制 |
| 客户端 stderr | 沿用 64 KiB 限制 |
| 完整任务记录 | 16 MiB，含最终换行；写入和读取同一限制 |
| 输入/任务记录 JSON 容器深度 | 最多 64 层，含最外层容器 |
| 可完成报告的有效深度 | 最多 62 层；报告外还有任务与结果两层 |
| 快照与报告 version | 必须为 Python 整数 1，拒绝 bool、float、字符串和 null |

字节上限包含原文件的空白、UTF-8 多字节及换行；恰好上限可以接受，多一个字节拒绝。仍保留原始输入字节及对应摘要。限额是已支持三模块的固定合同；扩展或改变复核模块时需同步审核合同及对照用例。

所有输入大小、JSON 和源码 UTF-8 校验发生在建立任务目录与调用 Docker 之前。验证仍包括源码/扫描摘要、受限路径和符号链接拒绝。语义合法性由实际批量复核器继续判断，例如未知规则、64 次检查和导入请求约束；本步不宣称已实现逐命中或 CWE 适用性校验。

JSON 拒绝重复键、NaN/Infinity、有限数语法溢出到无穷、非 UTF-8 编码和过深结构；不接受以 UTF-16/32 编码的原本可解析 JSON。深度在解析后以迭代器核对，解释器自身的嵌套异常也转换为输入错误；这不是流式解析或全方位 CPU/内存隔离保证。Python 这份版本合同比 JavaScript 解析后的数字类型更严格：JS 无法区分 JSON `1` 与 `1.0`；本步不宣称 Node 已能保留数字原文类型。

## 报告和原子记录

报告使用相同的 UTF-8/唯一键/有限值/深度规则。错误版本和编码在报告解析阶段记为 `report-invalid`，仍按精确 CID 清理，失败不发布完成回执。

写任务记录前检查完整嵌套深度、禁止非有限数并序列化，核对 16 MiB 上限后才打开临时文件。因此报告自己符合深度限制，嵌入任务记录后超限时也不会提交无法再次读取的完成记录。完成记录在这些预写检查失败时移除内存中的结果，保存 `completion-record-invalid` 的失败记录；存储错误仍沿用提交响应未知/原任务查询机制，不据此盲目重跑。

旧快照因 launcherSha256 已变而继续拒绝执行，新的验收需重新创建快照与质量冻结；不回填旧记录。状态/回执版本不变：快照 1、任务记录 1、执行回执 2、质量报告 6。历史记录若含本步拒绝的类型、编码、重复键或嵌套，可能无法通过新读取校验；原文件保留用于诊断，不自动改写成新完成结果。

## 验收与边界

Mac/VM 各 52 项启动器测试、9 项批量复核测试和 43 项 Node 质量门槛通过。初始 50 项测试中 19 个失败断言/子用例复现旧缺口；深度/指数补充阶段 51 项中 3 个失败、完整记录嵌套阶段 52 项中 1 个失败，均保留源码和日志。

实际 VM 使用原有固定镜像运行现有合成证据夹具与恰好最大字节批次，均完成且能读取原结果。最大批次为 8 个各 1 MiB 的注释源码、1 MiB 清单、8 MiB 扫描文件；不运行项目代码。源码/扫描/源码合计各多一个字节的控制在分配任务前被拒绝。真实容器的 bool 版本及 UTF-16 报告被记为 report-invalid，恢复未生成结果。四个任务按精确 ID、名称、标签和同源客户端探针稍后核对无遗留，收尾目录已清理。

日常 169 项程序、42 个项目库逻辑摘要和关键配置不变。插件源码未改，本步未重复运行完整插件套件；受影响的启动器、批量复核及门槛均在 Mac/VM 运行。

Claude Opus 5.5 high 已完成本步只读复审，无本步阻断。意见逐条核对并记账，未将剩余非阻断项冒称为已修复。[结构化验收记录](reviewer-input-boundaries-results.json)。

本步不部署日常 VM、不推送 GitHub、不扩大 Mac 权限、不新增独立准入样本。创建状态不收敛、记录建立前失败、长期日志保留、信号检查窗口和恢复审计字段等前一步边界继续见 [生命周期记录](reviewer-cleanup.md)。逐命中映射、运行 nonce、独立证据与新正负样本准入尚待完成，R3 未放行。

## 复审处置与保留限制

报告单独解析时接受至 64 层，嵌入任务/结果两层后的有效完成上限为 62 层；63/64 层会在提交前以 completion-record-invalid 拒绝。当前有 63 层失败控制，没有将 62 层正例冒称为已运行。UTF-8 预检也不保证 Python 可解析，含 NUL 或其他语法错误仍可能形成只有字节成员关系的回执；逐文件解析状态与逐命中映射另行处理。

严格 JSON 合同限于本启动器的输入、快照、复核报告和任务记录。Docker inspect/进程探针仍属于可信输出边界；Node 门槛未改，其 BOM、重复键、超大数及深度处理与 Python 不完全一致。转义的孤立 surrogate 仍可接受，不宣称 I-JSON 合规。

非法报告的清理先结清容器与客户端，stage 保留到显式 recover；完成记录无效是在 stage 已删除后失败。故障原记录仍需查询，退出码也不单独证明全部保存已结清。

报告的非典型字节可能在重新序列化后膨胀超过 16 MiB，预写上限会拒绝。本步大小失败测试使用缩小的同一上限变量；真实 16 MiB DEL 膨胀控制、恰好记录上限正例、更多 JSON/编码组合、VM manifest+1 及更精确的负面断言仍待补齐。失败记录补存报告摘要/大小、取消与记录无效并发时保留信号、私有记录数值字段的进一步类型校验也继续记账，未冒称修复。

外部模型收到当前变更源码、测试、差异和原生结果摘要，但没有收到 normal 输出、原始 cleanup/poll 及未改的 batch/gate 测试源码；原件在本地保留。中间红测源码也仅在本地后续核对字节，未纳入此次模型提示，不把这些后续归档核对说成模型已复算。

后续[明确未启动的创建恢复](reviewer-create-recovery.md)已处理新日志协议下有充分证据的未启动收敛；旧未知、记录/日志保留及其他准入边界仍继续记账。
