# R3 回执来源覆盖

2026-11-11，本轮修复旧回执只有不透明输入摘要、无法机械核对样本来源的缺口。旧实现即使收到无关项目的输入清单，只要调用方声明了正确的数据集与冻结摘要，仍可满足回执结构条件。上轮独立审查将其列为发布前需要处理的 N1。

## 当前绑定

启动器继续核对源码与扫描输出，并在回执版本 2 中保存 `inputFiles` 和 `scanSha256`。`inputFiles` 是执行时实际复制字节的逐文件 SHA-256：必须有 `manifest.json`、`scan.json` 及 1–64 个 `sources/` 下的受支持 Python 文件。清单键为受限 ASCII 路径，值为严格 64 位小写摘要，因此可复用现有 Python/Node 规范 JSON 摘要。回执的 `inputSha256` 等于整份清单的摘要，`scanSha256` 等于清单里的扫描文件摘要。

质量报告版本更新为 6。已完成、身份/数据集/冻结/时间绑定匹配且清单有效的回执才能贡献来源覆盖。当前快照处理 Python CWE-94/95 的 eval/exec 与导入流程；机械覆盖只校验 Python 字节成员，尚不校验 CWE/规则是否适用。当前候选策略仅包含这两类，其他类别未获得准入评估。评估器合并各有效批次的源码摘要，检查每一行 Python 来源，包括阴性和只用于诊断的样本；PHP、JS/TS、Java、C++ 等行产生明确的语言不支持阻断，不会仅因相同字节就计入覆盖。`manifest.json` 与 `scan.json` 的摘要不算源码覆盖。缺失来源在 `reviewerCoverage.missingCaseIds` 和逐例原因中列出，并增加准入阻断。

同一运行内，相同 `inputSha256` 只能出现一次；改变键顺序、回执时间或报告摘要不能绕过此检查。不同输入批次可共享辅助源码，覆盖集合按来源及案例去重，不增加样本数量。

## 兼容与验收

数据集、策略、冻结及运行输入仍为版本 2。旧版本 1 回执继续用于诊断读取，但不能提供本轮要求的来源覆盖。旧记录会增加清单缺失与覆盖不足阻断，并明确列出旧回执；v1/v2 混用也保持阻断，不改写历史冻结或回执。

初始 8 项回归在旧实现下失败；另补 64/65 源码边界和两项兼容检查（后两项在修订前 41 通过/2 失败）；修订后 Mac/VM 各 43 项质量门槛、10 项快照测试通过。Mac 全部 1,020 项插件回归通过。VM 复用了已有合成夹具，由固定镜像内的实际复核器产生版本 2 回执；Python 生成的输入清单摘要通过 Node 核对。无关来源、清单改动及重复批次的对照被阻断。现有 Xinference 历史结果回放保留旧诊断计数与全部旧阻断。

日常 VM 的 169 项程序、42 个项目库逻辑摘要和关键配置核对一致，临时目录已清理。本轮没有新增独立准入样本，不修改扫描规则、阈值、来源台账或日常部署。启动器字节已改变，旧快照会由启动器 verify/run 因 launcherSha256 不符而拒绝；Node 质量门槛不比对当前启动器版本；新验收须先重新创建快照和质量冻结，不回填旧快照。

Claude Opus 5.5 high 完成本轮独立复审，无本轮阻断。[结构化验收记录](reviewer-coverage-results.json)保留实际源码、回执、合成对照与复核摘要。

## 限制与剩余工作

来源覆盖只说明有效回执声明包含这些文件字节，不证明每个执行点已被实际分析、每个发现已被核实、扫描结果与源码语义相符，或报告汇总正确。原始输入、扫描输出、复核报告及其映射仍需独立复核。回执为本地声明，并非签名或外部封存。覆盖不足或语言不支持不会改写既有声明决策或类别计数；判断准入必须同时查看全局状态、阻断和逐例原因，不能单看类别指标。

此前审查指出的超时/信号下容器清理、大小上限统一、严格 Python 版本类型、VM UID/挂载路径校验和补充负面测试不在本轮修复范围，仍待处理。选样协议与未使用过的独立正负样本验收也尚未完成，R3 未放行。

参考：[Node SHA-256 输入](https://nodejs.org/api/crypto.html#hashupdate-data-inputencoding)、[Python JSON 序列化](https://docs.python.org/3/library/json.html#json.dumps)。

证据说明：初始红测使用 v1 夹具，未封存当时新测试文件字节，只保留运行日志。当前测试字节可核对的红测为两项兼容检查（41 通过/2 失败）；另有明确标为回顾性合成证据的 v5/v6 见证。

以下也仍待处理：空扫描或路径不匹配时的逐命中映射、缺少 run nonce/结束时间上界导致的跨尝试回执复用、改动清单字节后的语义等价批次。文件成员关系和相同输入摘要去重不代表这些问题已解决。
