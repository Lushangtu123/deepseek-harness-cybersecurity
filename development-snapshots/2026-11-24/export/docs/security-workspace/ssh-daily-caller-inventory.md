# VM 日常 SSH 调用路径盘点

已运行的网页入口由 launchd 加载，Node 在 49226 监听。独立的两次监听查询都将 49223 的 SSH 与 49224 的 HTTP 转发归到同一 QEMULauncher PID，记录中的 FD 分别为 21 和 20。查询是按端口分别取样，未追踪连接生命周期。未命中本地诊断和维护路由的普通网页请求、API 和 WebSocket 经 HTTP 上游 49224 转发。两个转发同在一个进程不足以证明它们共用同一瓶颈。

| 调用路径 | 实际传输与队列 | 证据 |
| --- | --- | --- |
| 已加载的网页入口 | 容量采样、时钟和环境状态经已安装管理器 SSH 队列。能力状态的所有者核对走 HTTP，显式切换则另调用管理器 | 已加载参数与路径匹配，磁盘源码摘要，调用点核对 |
| 网页恢复清单 | 管理器在宿主读取清单和镜像元数据，不经 SSH | 恢复清单与其两个分支的磁盘源码 |
| 统一启动器的 VM 操作 | 启动、状态、关闭和需要 guest 的维护经已安装管理器。SSH 关联采样也用该队列 | 导出入口源码和 27 项合成测试 |
| 手动 Trivy 库维护 | 检查经管理器 SSH 队列。恢复和同版本记账同时持 VM 生命周期锁和 SSH 队列锁。符合发布者等条件后的上传阶段持 VM 生命周期锁，直接启动 SSH 并绕过 SSH 队列。上传结束后的管理器启动检查再走队列 | 导出源码、8 项原有合成测试、一项拦截执行器的传输夹具 |
| 隔离验收中继与过去的并发诊断 | 当前导出的验收中继直接连接，并有单独的本地准入限制。历史诊断与网页后台的运行时调用关系仍待核对 | 当前导出测试中继源码、已归档诊断报告 |

当前检查范围内未发现网页后台的直接 SSH 调用。手动 Trivy 上传是可从导出菜单进入的直接路径。仅核实源码可达和模拟调用，未找到该路径与历史故障同刻运行的证据，也未核对用户可能持有的其他菜单副本。全量宿主调用方、外部脚本、临时终端命令和其他时刻的进程不在此次盘点范围。

已安装管理器与导出管理器的整文件摘要不同。逐项比较顶层语法节点，差异集中在容量采样函数。本轮以实际安装版为网页后台基线。容量采样和环境读取没有使用 VM 生命周期锁，因此手动上传即使持有该锁，从源码看仍可与它们的受管 SSH 重叠。时钟维护额外使用 VM 生命周期锁，其冲突分支返回忙碌跳过。现有管理器的 SSH 队列从准备到命令返回持锁，已有预算同时覆盖等待和执行。

现有失败缓冲保存 50 条，时间范围为 11 月 3 日至 8 日（洛杉矶时间）。其中 27 条为 queue-timeout，分布为 clock-read 16、native-check 10、service-readiness 1。这一分类表示等待超时前没有调用 SSH 执行器。其余记录包括 1 条 clock-read 连接重置、6 条 native-check 连接拒绝及 16 条远端或未知错误。日志只保留失败，没有成功分母、等待期间锁持有者或直接调用的记录。native-check 属多个入口共享的标签，不能把 10 条都归到容量监测。历史队列等待与转发连接重置应分别排查。

35 项现有回归通过。传输夹具只拦截启动参数并核对合成文件流，管理器状态调用与直接上传在夹具中各走预期分支。本轮的调用盘点未向 VM 发起任何诊断或维护请求。运行观察只保留 launchd 的匹配状态和监听 PID/FD，以及经限量和字段白名单整理的管理器日志摘要。


补核原有记录摘要一致。27 条队列超时的传输阶段均为 queue，执行退出码均为空。这说明这些记录没有对应的 SSH 子进程退出码，无法据此确认当时的占用者。

Claude Opus 5.5 high 因额度限制结束，同一份审查正文由 DeepSeek V4.1 Flash high 完整复核。本步骤确认阻断为零。根据审查补充普通 HTTP 的路由范围，拆开手动维护各动作的锁行为，并收紧历史并发路径的证据边界。模型报告和回执已校验。外部复核使用独立 VM 审查传输，临时进程和目录已清理。

后续先在受管队列补齐锁占用者类别、等待时间和请求结果的关联证据。这样才能区分长操作占用队列与转发层连接失败，再评估手动上传应如何纳入调度。
