# 命中位置：真实扫描与 Chrome 候选验收

2026-11-03（America/Los_Angeles）。本批只更新 VM 版候选源码。此验收批次结束时日常仍为165项；随后已完成[日常166项发布及完整原生验收](source-location-release.md)，以下保留候选期记录。

本轮将正式 `createJointPanel` 组件放入一次性页面，连接真正的 VM RPC 和默认扫描器，并在 Chrome 原生界面操作。它不是模拟扫描，也不是完整 Harness 聊天／systemd 部署验收。

## 用户可见的变化

“命中位置”显示文件、起止行列、末端不含的字节范围，以及可展开的源文件 SHA-256 和快照编号。列号明确采用 UTF-8 字节。同一行的不同调用点分别保留；脱敏副本说明原文件需要另行核对。字段或任务／副本绑定有误时保留上一页有效记录并显示错误，不推算缺失坐标。

分页与报告下载检查任务、快照、总数和游标。等待／取消回执只接受原任务；未确认的启动请求保留恢复提示。Python 证据同样要求有效副本摘要与明确来源步骤。缺失模型次数显示“未知”，非法次数拒收，取消中的任务显示“取消中”。

这些都是证据展示与回执校验。位置关联不证明 AST、内建函数身份、外部输入可控、运行执行或漏洞成立；所有合成命中仍为 `unverified`。

## 验收方法

一次性测试项目含 5 份自写 Python 文件：CRLF／制表符、同一行双调用、中文和 emoji 在调用前、简单辅助函数，以及常量对照。只运行现用固定 Semgrep 1.182.1、原 16 条规则；不执行项目代码、不调用 Kali／REA／PentAGI，不复制 DeepSeek 账号配置。

每个隔离会话只允许一次实际 runner 调用；重复启动拒绝，调用前登记尝试，失败及超额请求保留。验收核对：

- 实际运行中的 Docker 镜像、固定规则摘要、完整挂载集合、命令、用户、禁网及资源／权限限制。
- 扫描根目录就是该任务的受管副本，与原项目分开；完整文件集合、逐文件摘要、合成敏感值脱敏及扫描前后内容一致。
- 最终任务和步骤完成、身份／快照／扫描编号相符、7 条已关联且待验证的命中与 5 份文件报告完整。
- 从实际副本重新计算每个端点的行、字节列和绝对偏移；保留合成脱敏副本字节用于复核，不能只看界面渲染值。
- 已运行容器的 ID 在停止后不存在，Docker 服务正向对照有效，带扫描标签的容器集合恢复基线。

## 实际结果与修订记录

前两次独立会话各完成一次真实扫描、7 条命中和 Chrome 分页／下载；均已清理。首次材料复核指出验收器吞掉检查错误、失败调用留痕不足等问题；第二次指出最终 verdict 与任务／报告关联还不充分。原回执保留，不能用较弱的早期通过字段代替最终验收。

第二次会话额外独立读取实际副本，核对全部 7 个范围；下载报告与后台逐节完全一致。最终严格版会话完成一次真实扫描，7 条范围独立核对通过，Chrome 分页、同一行双调用、下载及刷新后原任务恢复通过。下载报告五节与后台完全一致，扫描子任务模型调用为 0。实际 Opus 5.5 high 针对性闭环复核未发现本范围内导致错误通过的阻断问题；其列出的真实运行前提均由最终回执核对。模型只做材料复核。

同一行双调用的最终受管副本位置为 `2:35–2:48`、`2:50–2:63`，字节区间分别为 `[59,72)`、`[74,87)`。原文件含较长合成敏感值，不能套用副本偏移。CRLF／制表符范围也逐端点核对。

Mac 和 VM 最终插件回归各 **778 项**，其中新增界面专项 19 项；验收器专项 7 项、清理解析专项 2 项；最终 VM 28 项针对性检查包含这两组及 19 项界面检查。旧扫描回放仍为 21／21／6 条收录，不是新扫描，也不是新独立样本。三个会话复用或调整的材料均登记为开发材料，新增独立准入样本为 0，R3 未通过。

最终停止后的清理检查出现一次已定位的误判：Docker 返回小写 `error: no such object: <容器ID>`，检查器仅匹配大写 `No such object`，因此拒绝认可容器缺失。原失败记录保留，临时目录当时未删除。随后按实际 ID 严格核对退出码、空对象结果、错误中的 ID 和固定镜像正向对照，确认不存在后再完成清理。修正后的解析器通过两项正反例和 VM 实际错误回执回放，没有为此再启动第四次扫描。正式候选程序未受这个一次性验收脚本问题影响。最终证据中的原 `cleanupErrors` 保留；整体结果单独标明清理恢复通过。

运行观察器还记录了一次容器建立前的暂时性 inspect 失败；后续实际运行容器的完整校验通过。这不是扫描或报告续读失败，也未将无观察状态计为通过。
