# R3 明确未启动的创建失败恢复

2026-11-11，本步处理 N2 中“已知没有启动却长期未确认”的收敛缺口。旧实现先设置 creationAttempted，再保存 creating 阶段；这次保存失败或 Popen 构造失败时，没有容器客户端实际运行，恢复却只能按未知创建等待。

## 新证据与恢复

新任务包含 `creationJournalVersion: 1`，这是当前生产者“create 事件在 Popen 前严格保存”的协议标记，不是签名或外部封存。顶层任务记录版本仍为 1。标记存在时必须是严格整数 1；旧记录缺少该标记仍可读取，但不能仅以缺失事件推断未启动。

在尚未成功创建、尚未观察到容器、没有 CID、CID 文件也不存在的前提下，可接受两类未启动证据：

| 证据 | 额外条件 |
| --- | --- |
| 没有 createClient 字段 | 新协议，保留的事件历史中也没有 create 事件 |
| 明确 notStarted 的 create 事件 | 新协议、正整数事件序号、已知原因、没有 pid/exitCode，历史中的 create 事件均与它一致 |

确认后将 creationAttempted 设为 false，保存 `creationNotStarted` 的依据和核对时间；它不表示成功执行，也不生成完成回执。之后仍查询精确 ID/名称并核对本任务客户端结束，才确认资源清理。身份不符、缺少协议、历史冲突、已有 CID 文件、存在 PID 或退出结果时不作这项推断。

Popen 的 OSError 仅在 Popen 构造调用处转换为 `client-spawn-failed`，并记录 notStarted；运行后的失败不进入这一分类。日志准备、严格事件保存、预启动取消等已知未启动错误也尝试保存相应事件。持久化失败时不假定证据已落盘，后续恢复以原记录及资源查询为准。

等待 Popen 之前又检查一次取消，缩小日志准备期间的取消窗口；检查和 fork 之间仍不是原子操作，不保证信号后绝无短暂启动。原始创建失败原因继续保留，恢复不重新 create/start。

## 保留策略边界

本步不加入按名称批量删除或未知任务自动放弃。保留策略核对后的顺序是：

1. 活动、创建/清理未知、记录缺失或损坏的目录继续保留，独立列出待处理原因。
2. 已完成或 recovered 且资源确认不存在、stage 已收尾的任务，才可以进入未来的只读保留清单。
3. 清单绑定原路径、记录与日志摘要、状态、大小和资源核对；保存审查回执与必要原始结果后，再由明确的清理动作执行，而不是一边列清单一边删除。

上述保留清单/总量策略尚未实现；当前没有跨任务总存储硬上限，也未增加自动删除周期或删除日常记录。缺少首次记录的孤立 stage、最终保存失败退出码、恢复审计字段分离和旧日志句柄等边界继续记账。

## 验收

Mac/VM 各 62 项启动器测试、9 项批量复核与 43 项 Node 质量门槛通过。初始失败阶段保留 59 项/6 失败，协议类型与取消断言修订后 60 项/7 失败；CID 冲突控制为 61 项/1 失败；首轮审查指出的损坏原因类型，在 62 项测试中复现列表/字典两项失败，增加字符串校验后通过。

VM 的真实正常复核仍产生绑定当前字节的原始回执；另两个显式故障注入控制分别触发创建前保存失败和 Popen 对不存在可执行文件的真实启动错误。前者无 create 事件，后者有未启动的 create 事件，两者均未执行 Docker create、未 start、未产生完成结果，recover 保留原失败并移除 stage。不是实际磁盘故障或全系统故障模拟。

三个任务按精确名称、已知 CID/标签及同源进程探针另行核对无遗留后清理本轮临时目录；日常 169 项程序、42 个项目库逻辑摘要及关键配置不变。旧协议、冲突历史/进程结果/CID 文件的未知保持由 Mac/VM 合成单元控制验证。插件源码未变，本步不重复完整插件套件。

## 首轮复审修订与补充边界

损坏的 notStartedReason 为列表或字典时，首轮候选曾在恢复及失败保护中抛 TypeError。本步已复现并修正原因类型校验；现在保留未确认和原失败，不产生结果。这里只处理该类型缺陷，不宣称所有损坏记录都可自动恢复。

日志准备或严格事件保存失败会设置 io_failed；即使内存已知未启动，原运行仍可能 cleanup-unconfirmed/退出码2，需证据成功保存后由健康 recover 收尾。此类端到端保存分支、已运行 create 的真实错误负例、额外历史/CID 符号链接冲突等测试仍待补充。

startedAt 是事件建立时间；creationAttempted 用于创建不确定性，不是不可修改的历史事实；更完整的审计字段分离继续记账。标记存在而版本未知/类型错误时，status/recover 整体拒读，不猜测未来协议。私有 _engine_factory 仅供可信、遵守同一前置事件协议的测试；任意替代引擎不获此保证，CLI 不开放该钩子。

原生控制中 Docker 未创建的字段是按构造推导（缺失执行文件或未调用 invoke），不是独立守护进程计数；无 start/无结果则有直接断言。初轮重复的镜像赋值在修订控制中已移除，原始证据保留。修订后的当前字节已重新运行正常复核及两个故障控制；本轮累计六个原生任务均收尾，最终当前字节验收计三任务。实际执行过、非零退出的 create 仍可能对应在途 daemon 请求，查不到对象时继续保持未知。

最终复审边界：第二轮包含 Mac 62 项原始输出；Mac 9 项批量/43 项门槛日志来自本步较早的实际运行，已提供第一轮且目标字节未变，F1 一行修订后没有在 Mac 重跑这两套；VM 已重新运行 62/9/43。首轮三个任务的清理原件由首轮材料保留，不与最终字节三任务混作一次验收。未来异常保护、成功 create 退出码等私有元数据严格类型及更多实际运行后失败控制继续记账。

后续[只读保留清单与容量预览](reviewer-retention-inventory.md)已提供本地计划与容量观察；原记录仍保留，归档/删除执行与写入硬配额未实现。
