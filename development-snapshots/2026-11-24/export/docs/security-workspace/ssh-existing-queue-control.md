# 现有 SSH 队列隔离交叉对照（已完成本步骤外部复核，研究工具复用仍有门禁）

实际日常 manager.py SHA 为69cc27ae…；导出为12dcfa4c…，两者仅storage_capacity差异，ssh_channel/ssh函数文本一致。本步固定日常实际字节，未从旧HEAD取代当前文件。

既有队列在完整命令期间持有同一文件flock，覆盖线程和独立管理进程；因此不应把刻意绕过队列的6并发诊断失败率当作日常排队入口失败率，也不新增重复队列。

本步4个分块，每块均运行 unqueued/existing-queue、各6个独立子进程。两者均使用自己拥有的IPv4临时监听、listen(1)、accept前等待25ms、单字节回显。共48次单次交换，无自动重试。25ms为每个trial开始的一次性接收停顿，不是每个客户端都等待25ms。manager.command被替换成回显函数，不执行ssh、不打开身份/known_hosts、不连接VM。全部子进程wait、服务线程join、临时监听和目录随上下文退出。

20次失败都是reply阶段ConnectionResetError/54，最晚在管道释放后0.541ms结束；对照服务accept返回首次为25.964–30.309ms。每个直接并发trial均1成功，队列trial均6成功；exchange时间区间峰值分别6和1。

这是本机合成交换对照。排队同时改变建连节奏、整次交换顺序及负载，无法独立区分connect限流与完整命令串行化；管道释放不等于网络同时到达。未测内核实际队列/抓包/原QEMU调度，未运行SSH握手或远端命令，不能证明生产13个失败逐例同因、未来零故障或生产性能。正常成功路径的收尾已执行，未注入communicate/kill/join本身失败，不承诺所有中断都能无残留。

已有队列回归11项：第一次沙盒内SIGTERM收尾用ps查询自有测试子进程受EPERM阻止；保留为环境失败，不记通过。仅该测试套件经范围受限执行重跑后11项通过。新增结果核对/来源门控8项通过；首次7项缺实现失败以及新增deadline handler缺失失败记录保留。测试只说明这些场景通过，不宣称产品全量测试。执行阶段源码/合约/结果和测试均固定到审查包。

复用暂不作为修复：官方OpenSSH文档说明master控制socket不存在或不监听时会回退另建连接。下一步若需要复用，先设计失效关闭、master/控制目录所有权、重启与取消、总预算、远端未知结果不重放；现有全命令串行队列已覆盖这一合成突发场景，应先寻找日常绕过队列的实际调用及必要并发需求。
