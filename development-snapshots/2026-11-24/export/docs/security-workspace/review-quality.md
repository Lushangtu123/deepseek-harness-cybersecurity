## 版本 4：样本选择参与资格核对

类别指标现在同时核对漏洞真值和行级 `selection` 声明。声明需包含最多 120 字符且不为空白的 `method`、布尔值 `blind: true`、`qualificationEligible: true`，以及 64 位小写十六进制的 `protocolSha256`。协议摘要指向预先固定的选样方法，内容、封存时间和代表性需要在发布复核时读取核对。

`blind: false`、`qualificationEligible: false` 或已知的 `curated-known-vulnerability-pair` 方法会产生 `sample-selection-ineligible`。字段缺失或类型不合要求会产生 `sample-selection-incomplete`。相关样本继续显示在 `diagnostic`，并列入 `excludedFromQualification`，不会参与合格数量、召回率或误报分母。

旧版数据集、冻结和运行记录仍可读取。缺少选择依据的旧样本按当前方法仅作诊断，原有冻结、历史报告和已用台账保留。输入版本继续为 2，报告版本为 4，数值门槛保持。选择字段包含在数据集摘要中，冻结后的任何修改仍会报告不匹配。每次尝试的使用声明仍包含全部输入源码，包括未计入资格的样本。

选择声明属于调用者提供的证据。格式检查无法证明协议真实存在、取样独立或没有根据结果挑选样本。已知配对方法按列明的精确名称识别，其他方法仍需人工核对其真实含义。正式新样本验收仍需完整冻结复核器依赖，并在运行前核对协议及来源使用记录。

Mac 和 VM 各 27 项专项通过，Mac 全部 1,004 项插件回归通过。历史 Xinference 结果重算时，原始旧数据的合格计数由 2 变为 0，诊断计数保持 2。显式标记的定向配对报告增加选择阻断，原有冻结和真值阻断继续保留。[本轮结果](review-selection-results.json)

## 版本 3：准入与诊断分开

新增独立来源正常路径后，Terminal 的 Opus 5.5 high 复核发现：旧版虽因真值等阻断不能放行，但自写阳性对照仍会进入类别召回率与最小数量统计，可能使某项指标看起来达标。修正后输出版本为 3，输入数据集/运行/冻结/策略仍为版本 2。

类别顶层计数和所有阈值只使用声明 `independent-vulnerability`、位置核对及适用条件核对均为 true 的样本。`diagnostic` 保留全部样本的结果，`excludedFromQualification` 列出其他样本。自写对照、仅有规则期望或真值核对未完成的条目不能抬高准入数量、召回率或稀释未知比例；真值不完整仍保留阻断。来源和核对标志仍需独立发布复核，字段本身不证明真实独立性。

此次是看过结果后修正评估方法，原始 v2 代码与报告已保存；v3 使用同一批原始扫描作回顾性纠错，不能算作新的独立验收。数值门槛与检测器规则未改。Mac/VM 各23项专项、748项插件回归通过。[v3结果](review-quality-v3-results.json)

`falsePositiveRateUpperBound` 只表示有限标注样本内把未知阴性按阳性计算的保守口径，不是总体误报率的统计置信上界。当前小型、人工选取的来源没有提供可推广的置信区间。源码中存在执行调用、运行时执行过、扫描器报警、复核确认分别记录，不能相互替代。

以下保留版本2及更早的历史设计与结果。

## 版本 2 修订

Terminal 中的 Claude Code 对固定源码做只读审查后，补齐了以下检查。旧版本 1 的结果保留在上面的历史记录中；当前入口要求版本 2 的数据集、运行记录、冻结记录和策略，台账仍为版本 1。

- 每个样本必须给出行、列位置。当前扫描按行定位，同一源码摘要、语言、CWE 和行号最多计一例；不同列号不能重复计数。原始命中的源码摘要、语言、CWE 或行号与样本不符时退回未知并阻断。同文件不同行的执行点可分别统计。
- 已决证据同时绑定源码摘要、样本编号和结论。同一产物摘要支持不同输入或不同结论时，相关结论退回未知并阻断。相同输入、相同结论的共用产物会单列，报告内部是否确实支持各样本仍需人工读取。
- 运行记录绑定数据集和冻结记录摘要；冻结绑定台账摘要。评估时重新读取该份台账，并核对已用源码集合。时间戳要求显式时区。
- 除已决样本误报率外，增加保守上界 `(阴性被确认数 + 未知阴性数) / 全部阴性数`。该上界也须达到同一个误报率门槛，不能靠把难例改成未知获得更好的准入结果。
- 未知按阳性、阴性分别计数，证据字段必须是有界对象数组；不合格真值和证据会列出涉及的样本编号。

这些摘要与时间仍由调用者提供，冻结本身没有签名。`freezeTrust` 明确声明需要在独立发布复核中核对事先保存的冻结摘要、台账和原始运行证据；仅重写 JSON 无法建立可信先后关系。此工具不提供防恶意评估者的远程证明。`eligible-for-release-review` 仅表示可提交人工发布复核，R3 和执行权限始终为 false。

冻结与评估均输出 `usageRequired`，列出数据集摘要和所有源码摘要。受控运行器或操作方须登记每次独立验收尝试，包括失败尝试，再进入下一次冻结。该离线工具不自动写台账，发布复核须核对登记是否完整。所有 JSON 摘要使用导出的 `digest` 规范化计算，不能用带缩进文件的原始字节摘要替代。

两组既有样本重新按版本 2 回放时，会标明是回顾诊断。它们已进入使用台账，当前冻结又晚于原运行，两组均保持 blocked，不称为新的独立验收。[版本 2 回放结果](review-quality-v2-results.json)。Mac 与 VM 的 20 项门槛测试通过，两组报告逐值一致。

## 指标与未知

评估按语言及 CWE 分组。每个固定样本记录真值、输入摘要、来源与位置/适用条件是否独立核对。原始扫描状态为 hit、no-hit 或 unknown。命中后的复核结论为 confirmed、excluded 或 unknown。没有扫描命中的已覆盖样本记为 not-required；缺失回执和未覆盖保留 unknown。

| 指标 | 分母和含义 |
| --- | --- |
| 原始误报率 | 阴性命中数除以扫描结果已知的阴性样本数 |
| 原始检出率 | 阳性命中数除以全部标注阳性 |
| 复核后误报率 | 阴性被确认为问题的数量除以已决阴性数量 |
| 复核后漏报率 | 原始漏报和错误排除的阳性数量除以已决阳性数量 |
| 已确认检出率 | 已确认阳性数量除以全部标注阳性 |
| 已观察误排除率 | 错误排除的阳性数量除以全部标注阳性 |
| 未知比例 | 未覆盖或命中后仍未定论的样本除以全部样本 |

分母为零时返回 null。误报率与漏报率的已决样本分母同时显示，未知比例独立检查。全部命中仍待核实时，复核后误报率和漏报率均无法计算；已有白名单证据的命中仍属于未知。已观察误排除数为零也需同时查看未知比例，不能据此认定复核过程安全。

已决结论要求人工审查或沙箱核实的证据引用、产物摘要及匹配的输入摘要。模型断言、单独条件观察和输入不匹配的证据按未知处理。这里检查证据声明的类型、输入绑定和摘要格式，产物内容是否足以支持结论仍须独立复核。

## 冻结与候选门槛

冻结绑定数据集、候选扫描器、规则、复核器和门槛摘要。冻结须早于运行。候选或门槛改变后需重新冻结并重跑。[样本使用台账](review-sample-ledger.json)记录已用于开发或外部回归的源码摘要，已使用的源码不能再次由冻结入口接纳为新样本。按字节摘要去重无法识别所有语义或模板复用。

我为 Python CWE-94/CWE-95 设置了以下候选默认值，供后续校准，尚未成为生产准入配置。[候选配置](review-quality-policy.candidate.json)

| 条件 | 候选默认值 |
| --- | ---: |
| 每类别最低标注数量 | 阳性 20、阴性 30 |
| 原始检出率 | 至少 90% |
| 已决样本的复核后误报率 | 最多 5% |
| 已观察误排除率 | 0 |
| 未知比例 | 最多 20% |
| 已确认检出率 | 至少 90% |

这些是有限样本上的候选目标，未提供总体效果保证或置信区间。其他语言和 CWE 需要单独配置。缺少独立漏洞位置与适用条件真值、样本不足、规则/工具变化、读取未覆盖或关键指标无法计算时，结果保持 blocked。即使候选指标达标，输出也仅为 eligible-for-release-review，R3 和执行权限仍由正式准入维护。

## 本轮实测

- **历史 OWASP Python 53 例**。原始阳性命中 20/20、阴性命中 33/33。22 个阴性虽有条件证据，全部 53 例仍待核实，因此复核后误报率为 null、未知比例 100%。53 个源码摘要均命中开发使用台账，阻止把历史诊断结果再次当成独立留出验收。
- **新冻结的外部 Django 回归**。候选和门槛在读取结果前固定。Semgrep 上游文件有 3 个阳性和 1 个阴性标注，宽泛 eval 规则命中全部四例，现有复核器未给出已决证据。该文件的标注针对上游规则，原注释有的位于取值行，本批依据同一函数内唯一执行点关联。它是外部规则回归，尚无符合 C1 的独立漏洞位置及适用条件证明，也未达到候选最低样本数。结果保持 blocked。[固定上游样本](https://github.com/semgrep/semgrep-rules/blob/16b9e6d45f10649f6a531ec4838ed9924372c3bc/python/django/security/injection/code/user-eval.py)

原始扫描在专用 VM 的固定 Semgrep 镜像、禁网只读容器中运行，解析错误为 0，临时容器与输入清理通过。候选 Python 复核器也在 VM 中读取这些固定文本，没有执行样本代码。质量评估器的 9 项回归在 Mac 与专用 VM 通过，两套评估报告逐值一致；插件回归共 734 项通过。此入口未接入自动发布，也没有放行普通检查。

## 命令行入口

准备五份普通 JSON 文件：数据集、候选策略、三个候选身份摘要、已使用源码台账和复核器快照清单。当前准入要求 identity.reviewer 绑定完整快照。冻结候选输入时使用以下命令；详见[复核器依赖快照](reviewer-dependencies.md)。

```sh
node scripts/review_quality_gate.mjs --freeze DATASET.json POLICY.json IDENTITY.json LEDGER.json REVIEWER_SNAPSHOT.json > FREEZE.json
```

运行结果包含同一候选身份、实际开始时间和每个样本的扫描/复核结果。评估命令如下。

```sh
node scripts/review_quality_gate.mjs DATASET.json RUN.json FREEZE.json POLICY.json LEDGER.json
```

退出码 0 表示可送发布复核，2 表示有阻断项，1 表示输入无效。JSON 输出同时保留计数、指标、未知比例及阻断原因。每份输入最多读取 2 MiB。新增回归已纳入既有插件测试入口。

## 版本 6：回执来源覆盖

[回执来源覆盖](reviewer-coverage.md)要求版本 2 回执内的 `inputFiles` 与 `inputSha256` 一致、`scanSha256` 匹配清单，并合并全部有效完成批次的源码摘要。当前快照仅支持 Python；其他语言明确阻断。缺失 Python 来源（包括诊断案例）、旧回执和相同输入的重复回执增加阻断；逐案例列出未覆盖原因。旧回执继续可读，但不能补足覆盖。来源成员关系不等于每个执行点已被核实，原始产物真实性与逐命中汇总仍待独立复核。
