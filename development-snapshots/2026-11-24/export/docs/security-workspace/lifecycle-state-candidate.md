# 状态与任务生命周期候选

本轮处理 UI-F1、UI-F2、PTC-F1、EXEC-F1，延续上一轮证据与脱敏候选。候选保持 172 个插件程序文件，并修改一份 VM `dsh-tools` 覆盖文件。本轮不部署日常 VM、不提交或推送；日常 169 程序 / 16 规则及原版功能保留。

## 原版能力开关

完成提示需要同时匹配本次 POST 返回的操作 ID、请求目标、成功状态及当前插件就绪观察。旧操作成功、另一个操作或丢失的提交回执，都只显示当前观察和本次未确认，不自动重发。

读取中、切换中、失败和插件状态不一致时，撤销父组件缓存的已核验能力，原版编辑区随之失去就绪状态。之后只有新的可靠观察可恢复就绪。

## PTC 调度

分类、启动、准备、派发、提交和日志基础设施异常都使外层调用失败。受影响项明确结算，待执行项取消，已派发的 owned 工作保持跟踪并在真正结算后排空。正常的并行上限、排他步骤和有序提交保留。基础设施异常与工具正常返回的 `isError` 分开处理。

取消只发出取消信号，不能证明任意工具已经停止。不响应信号、永不结算的第三方工具仍需自身的有界执行和停止验收；此候选不会通过丢弃 in-flight 记录伪装清理完成。

## 项目故障隔离

保存项目范围和执行隔离静态扫描（Semgrep/Trivy）只检查当前项目的应用转换状态，并保留工作台已知的活动任务排他。其他项目的损坏库、缺失库不再通过全局枚举使这些操作抛出 SQLite 错误。数据库初始化失败时关闭未缓存句柄，避免重复检查泄漏资源。

共享应用运行、ZAP 网络检查和联合任务继续检查全局状态。不可读取或运行记录无法解释的项目被标为 `unavailable`，不视为空闲，不声称清理完成，并保守阻断这些共享操作。健康项目的预检显示未知警告；坏项目内容不被自动修改、删除或重建。修复或恢复该项目、重新核对后才解除未知。

这是按操作范围隔离故障，不代表坏项目本身已恢复。未知项目仍可能持有旧运行，不能忽略后开启共享执行。

## 验收边界

新增测试使用合成回执、真实临时项目数据库，以及从发货代码提取的 `run_code.execute` 与惰性注册表/运行时。严格子进程模式将未处理拒绝、排空超时或残余 active 工作直接判为失败。UI 模型与 React 钩子夹具验证实际控制函数；这些测试不是日常实例完整浏览器或真实模型调用验收。

详情见 `lifecycle-state-results.json`。R3、完整工作区和真实项目 95 条待验证发现不因本轮回归通过而完成。
