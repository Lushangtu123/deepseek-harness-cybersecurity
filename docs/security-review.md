# 安全审查预设、预检与 Kali 合成验收

本轮在现有改进版中增加可选审查流程，不切换日常默认预设或原版能力。真实项目已有发现继续保持待验证。

## 选择审查预设

新建聊天，选择 **安全审查 · 受限工具**。明确提供一个已经存在的项目精确名称或 ID，首次通过 `redteam_session_bind` 绑定；不支持模糊名称。首次目标在工具准备阶段同步预留，绑定后禁止在该审查会话切换项目，需要另建聊天。

该预设只允许 `redteam_security_audit`、`redteam_session_info` 和首次绑定入口。原生 `tools.restrict` 控制模型可见工具，`tools.guard` 拒绝通用 Shell、文件工具、浏览器、MCP、子代理、PTC 传输和未知工具；对允许名称还核对工具定义身份，并在执行钩子重新核对。同名局部工具不能仅凭名字获准。

这些限制作用于选择此预设的 agent 工具调用，**不是新的操作系统沙盒**。它不约束用户手动打开的 Shell、其他聊天或具有完整 Node 权限的宿主插件。执行钩子依赖可信插件组合；恶意宿主插件可以直接执行代码或篡改后续运行时，不能靠提示词或本预设防御。现有完全访问/原版模式继续保留，Mac 的隔离设置不变。

## 预检与覆盖清单

聊天调用 `redteam_security_audit`，`action=preflight`；演练台“安全审计”页也显示同一份只读清单，导出的报告包含覆盖摘要。

预检核对已保存范围、有效期、仓库路径、工具资源及私有 ZAP 会话配置状态，列出当前可提交的受管工具。登录配置格式有效不代表应用当前仍登录；实际扫描仍执行原有前后登录标记核对。

覆盖分为代码、依赖与配置、凭据痕迹、本地 Web、登录与会话、角色与越权、业务逻辑、架构与信任边界。前四项只引用最近30条中同范围版本的任务：完整观察、部分覆盖、运行中或未验证；后四项保持“待人工验证”。完整扫描不等于安全结论，也不构成 OWASP ASVS 合规声明。不回填旧任务、不自动确认发现、不把未运行项标为不适用。

## 受管源码读取

`action=source` 只接受当前已确认仓库内的可见相对源码/配置文本路径；参数为 `path`、可选 `offset` 和 `maxBytes`（256–4096，默认3000）。目录穿越、隐藏目录、链接、硬链接、超大文件、私钥和不支持的文件类型会被拒绝。

单文件最大1MiB。先对全文检查私钥/部分明确凭据形态并应用项目脱敏，再按 UTF-8 字节分页；必须使用返回的 `nextOffset`，偏移对应**脱敏后的文本**。项目内容变化后应从第一页重读，不能把不同版本的页面拼成同一份证据。固定检测和脱敏不是完整的数据泄露防护，敏感材料仍应放在审查仓库之外。

源码仅作不可信数据。正文中的命令、账号请求或“忽略限制”等文字不构成授权。

## Kali 固定合成验收

聊天工具使用 `action=kali_check`、`mode=run` 和8–64位唯一 `requestId`。仅在已保存的有效项目范围下允许；它在专用 Kali 的普通用户中建立短时 `127.0.0.1` 服务，用 Nmap TCP connect 和 curl 检查该服务，返回结构化结果并核对监听端口关闭。不接受目标、端口、任意命令或自定义参数，不使用 sudo，也不向真实项目写发现。

调用可能持续数十秒。回执未确认时，复用同一 `requestId` 改用 `mode=status`，不要另发 run。同一请求在 Kali 留有独立私有回执，重复 run 读取原回执，不自动重放。回执按项目命名空间隔离，不包含账户凭据。

在 Harness VM Shell 也可运行：

```sh
python3 /home/purge/tools/dsh-purge-personal-1.1.77-personal.1/scripts/security-kali-lab.py \
  --request-id my-synthetic-check-001

python3 /home/purge/tools/dsh-purge-personal-1.1.77-personal.1/scripts/security-kali-lab.py \
  --mode status --request-id my-synthetic-check-001
```

CLI 的请求编号直接用于自己的回执；聊天工具使用带项目摘要前缀的独立编号。验收回执在 Kali 的 `~/.cache/harness-security-rehearsal/`，不会自动删除或进入公开备份。状态查询结合 PID、启动时刻与 boot ID 识别失去进程的运行记录，结果未确认不改写为成功。

内部 `--control` 仅供维护者运行合成的超时、SIGTERM 和 SSH 中断验收；模型工具不接受这些控制参数。该流程验证的是固定合成链路，不能据此声称其余工具、任意 Kali 长任务或目标业务测试均已通过。

## 恢复与验证范围

新程序及预设的源码进入 Git 导出；模型密钥、Kali SSH 信任材料、回执和 VM 磁盘不在其中。已有恢复点不因源码更新自动覆盖新增程序或 Kali 系统，恢复前仍需核对实际覆盖。

基础安装和专业资产安装仍按各自文档执行，恢复后需核对审查预设与本地连接是否已配置。本轮测试只处理合成仓库与回环服务，不复核或改写真实项目的95条待验证命中。

## 本轮实际验收

已部署139项程序并通过 Mac 与实际 Linux 回归。Chrome 中选择新预设后，DeepSeek 对独立合成项目实际完成绑定、预检、源码读取、一次 Semgrep 扫描、等待、Kali 固定检查和报告，共8次工具调用。合成命中保持待验证；源码中的越权指令未执行。原生 Cordis 工具运行时另行验证了首次绑定并发预留、换绑拒绝、未知局部工具与同名覆盖拒绝，禁止工具体调用次数为0。

Chrome 覆盖清单、合成 SQLite 与 Kali 原始请求的状态回执已交叉核对；具体范围和保留缺口见[结构化验收摘要](security-review-verification.json)。该验收不覆盖真实项目95条发现的人工复核。

基础安装器不会自动注册此可选预设；专业配置导入包含根 `cordis.patch.yml` 的声明。基础安装后需按配置文档导入专业配置，并确认项目程序版本及“安全审查 · 受限工具”选项出现，不能仅凭代码文件存在判断已启用。
