# VM 运行应用面板

在改进版演练台的“安全审计”页，先保存项目目录、ZAP、本地 HTTP 根网址和授权到期时间，再使用“运行应用”。这项入口只在 VM 改进版生效。

1. 填写项目中的 `.py` 入口和30–900秒时限，点“核对执行副本”。面板显示源目录、本地网址、文件数量、排除/脱敏统计和副本 SHA-256。预览最多保留5分钟，源码临时副本随即删除。
2. 核对信息并勾选执行确认，再点“确认启动应用”。启动器会重新捕获并核对文件集合、范围版本和固定镜像；有变化便拒绝执行。运行期限同时受项目授权到期限制。
3. 等待“已就绪”。面板的单次完整性核对只说明当前观察；只有同一联合 ZAP 扫描前后均匹配，才显示源码版本关联通过。
4. 需要提前停止时，勾选停止确认，点“确认停止或核对清理”。在启动回执不明确时，也可按保留的原请求取消。倒计时为估算；“清理已确认”以后台核对为准。

刷新或重新打开网页只查询原请求，不会重发启动。不要因超时改用新请求号；先核对或取消原请求。后台在开始取消前持久记录状态，应用切换尚未确认时，另一个标签页也不能启动受管扫描、联合任务或修改范围。

页面保留启动请求号、预览号和停止请求号，以便回执丢失后查询。服务端以项目内持久请求记录防止重复执行；独立 VM 临时服务持有启动器和期限，审计后台重启后仍能查询原应用。VM 关机不自动重启应用。命令行运行器仍可手动使用；页面只控制通过页面创建的原请求，外部命令行应用需要按[原命令入口](runtime-source-link.md)核对。

该面板不向模型开放启动/停止工具。模型仍可对已明确启动并就绪的应用选择联合审查步骤。受管应用目前限 Python 标准库独立入口，不安装第三方依赖、不构建项目。容器、固定 HTTP 转发、独立期限及证据边界沿用[运行源码关联](runtime-source-link.md)：这些记录不证明依赖、可复现构建或进程内存行为。Docker内部网络也不隔离VM宿主网关服务，同一UID原版Shell不属于私有记录的信任边界。
