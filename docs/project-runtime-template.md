# PhishGuard 隔离运行模板

VM 改进版的“安全审计 → 运行应用”新增“PhishGuard FastAPI（固定离线依赖）”模板。先保存有权检查的项目目录、本地 HTTP 根网址和有效期；选择模板、核对副本和固定依赖摘要，再明确确认启动。入口固定为 `app.py`。刷新只查询原请求；需要停止时按原请求确认清理。

这个模板针对当前 `Phishing-Scam-Email-Detection` 安装，保留标准库 Python 模板。它不会自动安装依赖或接受任意项目 Dockerfile。

| 对象 | 固定与核对方式 |
| --- | --- |
| Python 依赖 | 原有 Python 3.12 安装树，41 个发行包、7283 个普通文件，逐文件 SHA-256；未升级原项目虚拟环境 |
| 解释器与镜像 | 已有 GNU/ARM64 Python 镜像固定摘要，依赖只从 `/opt/harness-deps` 导入，以 `-I -S` 启动 |
| 审计源码 | 与联合审查共用脱敏副本及文件摘要；JSON 按结构处理，Python 只用可信静态解析器处理，不执行源码做脱敏 |
| 运行资源 | 单独记录 `website/static/vendor` 与 favicon，最多500项、单文件8 MiB、合计32 MiB；凭据名称和私钥材料拒绝 |
| 容器 | `network none`、非 root、只读源码与根文件系统、512 MiB内存、1 CPU、64进程上限、32 MiB临时空间、删除 capabilities |
| HTTP 检查 | 固定短时 `docker exec` 通道，仅访问本容器回环8080；不发布容器端口，不连接 VM 网关服务 |
| 期限与清理 | 既有 VM 独立临时服务持有期限，提前停止或到期后核对容器、转发、通道子进程及原网址记录 |

依赖冻结只证明所记录的已安装文件与镜像身份，不证明依赖无漏洞，也不是从源码到 wheel 的可复现构建。原安装依赖树、私有完整清单与镜像不上传公开仓库；迁到新 VM 需要恢复对应私有介质或重新审阅并生成锁定版本。构建入口 `scripts/security-runtime-template-build.py --confirm-build` 仅用于已满足锁定前提的专用 VM；已有构建目录会拒绝覆盖。

模板关闭 ML 私有模型加载、邮件/域名/SMTP/RDAP外部核验、真实账号、持久案例与发送者历史；不交接 `.env`、模型 pickle 或安装目录。只能验证离线核心功能。脱敏后的占位值可能影响应用行为；遇到无法安全处理的源码、重复 JSON 键或敏感数字等情况明确拒绝复制，不自动绕过。

服务器禁网不限制用户浏览器：页面可能包含外部账号链接，浏览器访问外链仍使用浏览器自身网络。当前 VM 回环网址也不是 Mac 浏览器直接打开应用的转发入口。模型不能通过新增 RPC 启动或停止应用，只能审查用户已明确启动的应用。

联合 ZAP 的前后核对涵盖审计文本、额外运行资源、固定依赖摘要、容器/期限/转发身份及资源限制。只有两次均匹配才标记 `managed-source-copy-matched`；这不证明进程内存或所有响应的来源，不代表安全结论。工具命中保持待验证。同 UID、已获授权的原版 Shell 仍在此证据机制的信任边界内。
