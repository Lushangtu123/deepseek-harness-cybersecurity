## 第一阶段背景

此更新只部署到专用 VM 的改进版 Harness。默认日常预设、“安全审查 · 受限工具”和原版能力继续保留。没有修改 Mac 版 Harness、Mac 权限、UTM 共享或网络控制。

## 使用

1. 在演练台“安全审计”保存项目范围和允许的扫描器。需要 Kali 时，勾选“允许联合审查向专用 Kali 交接本项目脱敏 Python 副本”，再确认保存。模型不能修改这个授权。
2. 在同页“联合安全审查”核对范围，选择已授权的 Semgrep、Trivy、ZAP、Kali、REA、PentAGI 中需要的步骤后启动；也可新建聊天，选择“联合安全审查”预设，明确指定已有项目，让 DeepSeek 调用 `redteam_joint_review`。
3. 保留返回的任务 ID。断线后用 `status` 或 `wait` 查询原任务；启动回复丢失时也可按原 `requestId` 只读查询。不要换请求号重复启动。
4. 下载联合 JSON 报告；聊天报告分为 `findings`、`files`、`exclusions`、`diagnostics`、`artifacts`，逐页读取至 `page.complete`。任务中的总数、保留数量及截断标记说明哪些明细没有收录。

例如：请对已授权的“示例项目”做联合审查，先核对范围，根据文件类型选择步骤，列出工具命中、覆盖缺口及证据来源，保持发现待验证。

## 当前执行范围

| 步骤 | 工作 | 限制 |
| --- | --- | --- |
| Semgrep | 固定副本上的源码规则检查 | 继续保留语义解析失败和有限文本补查的区别 |
| Trivy | 固定副本上的依赖与配置检查 | 使用原有离线镜像、漏洞库和规则；脱敏与排除内容未覆盖 |
| Kali | 普通用户的 Bandit 1.9.4 离线 Python 检查 | 不执行项目代码，不探测网络，不使用 sudo |

第一阶段当时仅开放三步骤；当前 .4 的新增适配器继承范围、预算、取消和证据约束，原有直接入口继续保留。

## 固定副本与证据

副本最多 1000 个可见文本文件、单文件 1 MiB、合计 8 MiB，目录遍历最多 10000 项、20 层。不支持的文件、链接、硬链接、隐藏路径、构建/依赖目录、二进制和明确凭据材料被排除；排除清单只保留前 20 个路径，记录实际计数与截断。

复制前应用项目脱敏，逐文件保存原始内容哈希与交接内容哈希。脱敏可能改变语法，解析失败必须进入覆盖缺口；这不是完整的数据泄露防护。敏感资料应放在项目审查范围之外。

只读取普通 `.git` 目录中的 HEAD/ref/packed-ref 文本，不运行 Git，也不读取或执行项目 Git 配置、fsmonitor、clean/process filter。工作树是否有未提交修改保持未知；实际检查内容由逐文件哈希固定，不把提交号当作完整版本证明。链接式 Git 工作树或无法读取的元数据不填充推测值。

扫描前后核对副本的完整文件集合及内容哈希；Kali 只收到其中 Python 文件，哈希与同一副本关联。副本目录和私有回执仍由 VM 用户持有，此设计不能对抗同用户的恶意高权限插件。现有完全访问环境也不是新的操作系统沙盒。

联合子扫描结果写入独立证据表，不更新普通审计发现的状态、备注、修订或证据。精确重复的同工具、同规则、同位置、同来源任务会合并；跨工具结果保留各自来源，不自动合并为已确认漏洞。

## 生命周期

联合任务由 VM 安全审计后台持有。默认总子任务时限 360 秒，可设 30–900 秒；授权更早到期时使用较早期限。到期或取消后仍允许有界的停止核对时间，无法证明停止时报告“未确认”，阻止新联合任务，不把强制断线当作取消成功。

此时限不包含 DeepSeek 对话费用；第一阶段当时不启动额外模型子任务；当前 PentAGI 的 16 次请求限额及模型费用见适配器文档。Kali 单次工作最多 90 秒，通过独立私有任务 ID、PID/启动时刻/boot ID 和进程组核对任务。工作进程异常退出后，可按原 ID 取消并核对存活子进程。身份不匹配或无法证明停止时保留未确认，不猜测其他进程身份。

服务重启将运行中记录标为中断，不自动重跑。网页会保留未确认的启动请求；后台明确拒绝且尚未创建任务时保存拒绝回执，查询后才能清除该提示。资料损坏、存储不可用或传输中断不会被推断成未执行。

副本、任务和回执保留在私有 VM 目录，不自动进入公开源码仓库。新增程序与 Bandit 安装不会回写已有离线恢复点；恢复旧点后必须按哈希锁文件重新安装并核对 Kali 工具。

## 结果解释

`completed` 只表示已选步骤执行结束，不能表示项目安全、漏洞已复现或覆盖完整。登录、角色与越权、业务逻辑、架构、未选工具和排除内容保持未验证。工具命中始终先记为待验证。

Kali 使用隔离用户环境 `~/.local/share/harness-security/bandit-1.9.4`，实际运行前通过该解释器读取安装版本。依赖的官方 PyPI 版本与 wheel 哈希固定在插件 `scripts/security-kali-bandit-requirements.txt`；恢复或迁移安装必须使用 `pip --only-binary=:all: --require-hashes`，不能直接以未固定的最新版替代。
